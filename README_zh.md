# Ninebot 九号 Home Assistant 集成

2.0 使用固定版本 `ninecli==0.1.7` 的 App 协议，替换旧 OpenClaw 查询链。
项目独立开发，与九号/Segway 官方没有隶属关系。

**2.0.0b17 为测试版**，安装前请阅读升级说明、[发布说明](https://github.com/Wuty-zju/ha_ninebot/releases/tag/v2.0.0b17)
和[实体迁移矩阵](docs/2.0-实体迁移矩阵.md)。

在 HACS 添加自定义集成仓库 `Wuty-zju/ha_ninebot`，选择测试版；
安装后由用户自行重启 HA，通过“设备与服务”添加 Ninebot。最低 HA 为
2026.1.0，CI覆盖 2026.1.0/Python3.13 与 2026.9.4 / 2026.10.0b0/Python3.14。ninecli 发布了
Linux musl/glibc、macOS 与 Windows 的64位 x86/ARM wheel；包存在不代表所有
平台均已实测。不支持 ARMv7/32位。后端面向中国区 App 服务，其他地区未验证。

登录先在私有候选目录验证，再查重和提交。配置条目不保存密码。失效会话通过 UI
重认证恢复；重认证不允许换账号。本地 REST 子进程只监听 loopback，使用随机
Bearer 认证，密码通过请求体传递，不进入命令行参数。会话保存在
`.storage/ninebot_v2` 私有目录；同权限或高权限进程仍属于本地信任边界。

默认状态轮询120秒，BMS/行程600秒，列表3600秒。按账户串行，按车辆和数据组判断
新鲜度；单车失败不拖垮整个账户。初始发现后按已启用实体及内部模型决定请求组，
禁用全部BMS/行程实体且无估算模型/骑行事件依赖时停止对应常规轮询。空或匿名
多包inventory保留每小时稀疏发现，首次BMS失败按既有退避重试。本地定时通知使过期数据和跨月汇总及时变为
不可用，不增加云端请求。缺失不填零，真实零保留。

不完整的云端车辆列表不能证明解绑：实际返回的车辆正常更新，未返回车辆保留
此前身份时间并暂时阻止控制，不被其它车辆的成功无限续期。发现失败保留原生
路由缓存；安全诊断分开显示整批完整性和每车身份时效。见
[发现契约](docs/v2x-不完整车辆发现与缓存恢复契约.md)。

主实体提供车辆真实SOC、云端精准续航、充电、主电源、解锁状态、电池实测电压/
温度和当月里程。普通/AI续航、最近行程与车型图片默认显示，原始耗电/功率诊断仍默认关闭。BMS
循环次数检查支持标志，不将不支持设备返回的100次当作真实数据，也不将score0
当作健康度0%。HA的锁二元传感器 on 表示“已解锁”。

电池实体保留原 ID：车辆级电压/温度仅在唯一上报电池时取值，多包不擅选主包；
带身份的分包测量按身份匹配，失去身份即 unknown，不按数组索引换包。当前仍挂
车辆设备；真实稳定电池身份和组成未确认，因此暂不自动创建 Child Device。
详见[电池身份与设备模型契约](docs/v2x-电池身份与设备模型契约.md)。

行程ec和charging_power单位尚未独立核验，因此只提供无单位、无统计类型的可选
诊断，不能当作 Energy Dashboard 能耗表。有可靠起止时间的行程按时间选择最近
记录；旧无时间结构保留最后返回值，排序未知。云端分页与月份完整性尚未核验，
上月回退仅补充最近行程，不覆盖当月合计。坐标系尚未核验，
位置展示需主动选择，不承诺自动GCJ/WGS转换。

SOC能量估算默认关闭。启用后手动设置标称电压与容量，新用户没有默认72V/20Ah。
估算公式为 `V×Ah×ΔSOC/100/1000` kWh，不是实测储能、充电器输入或精密计量。
长失联、异常跳变、数据源/参数变化重建基线；新模型generation使用新实体身份，
不改写旧历史。重启/重新启用时保留累计量而重建采样基线，不跨停用时段记账。
跨日/月区间按接收时间归桶，属于估算；不由SOC推导瞬时功率。

控制需主动启用并逐车允许。认证有效、车辆存在、profile/status有效且查询无错时可发送命令；已知拒绝或歧义能力仍阻止。未知权限保持未知，由九号云端最终鉴权与判断车辆支持。“可发送命令”不表示物理动作已完成。命令仅发送一次，不自动重试，随后回读状态。锁状态由二元传感器展示，旧不可用 Lock 已移除，engine不映射lock/unlock。当前策略及已授权实测见[b15契约](docs/v2x-云端鉴权控制与实测契约.md)。

升级前备份 HA 配置和`.storage`。兼容自研与fork两种旧配置：fork会话复制到
新版目录，原文件保留；旧OpenClaw用户通过App重新认证，迁移不后台反复登录。
同口径实体保留身份、用户命名与禁用设置。地址、GSM、上报时间和旧估算实体没有
可靠替代且在明确废弃清单内时清理注册表，不伪造值；云端行程耗电不覆盖本地估算总量。

旧满电续航参数没有实际用途，随废弃实体清理移除。旧锁编码诊断保持
0=锁定、1=解锁；App反向编码在适配层归一化。建议自动化使用锁/解锁实体。车辆身份不按昵称模糊合并，
不直接修改recorder SQL。回滚须同时恢复原集成版本及对应配置/存储备份；仅降级
代码不能逆转ConfigEntry schema升级。

详见[英文说明](README.md)、[开发报告索引](docs/README.md)。报告明确区分源码、
反汇编、实测与候选设计。新版 serve 后端已通过隔离会话副本完成一次两车真实只读查询，HA流程、迁移、
回滚和生命周期由合成测试验证；详见[预发布验收](docs/2.0-预发布验收.md)。真实
新密码登录、刷新恢复、其他平台和全部车辆控制仍需独立验证。未获得完整Go源码，
不声称已完成完整源码审查或可重复构建。

估算存储版本无法识别时停止加载并保留原数据，通过“修复”提示处理。会话回滚
若无法卸载使用新会话的运行实例，将保留事务和旧会话备份，提示用户自行重启
以恢复；开发与发布过程不操作运行中的 HA。

## 2.0.0b9 控制与原始数据说明

控制必须同时满足用户启用、车辆白名单、有效的新鲜数据，以及集成已验证的
上游支持、权限和动作语义。当前 opaque/null 权限无法证明授权，硬件控制保持
不可用。锁定状态由二元传感器展示，旧不可用 Lock 实体移除，
不把 engine-start/stop 当作 lock/unlock 执行；只读刷新不受影响，控制测试全部使用模拟后端。

原始业务响应仅保存在有界私有内存中，凭据及个人资料先移除。诊断只导出
审核过的字段路径、类型和计数，不导出值、任意未知键或精确坐标。九份历史与新采集
脱敏payload以及单独标注的图片字段选择样本可离线重放；身份、图片、坐标和时间安排明确替换为合成值。非空行程
和详情结构、Unix秒/中国时区关系已只读确认。距离与服务端最高速度采用ninecli
显示契约的km与km/h，未独立核对App展示；轨迹速度/距离增量单位、坐标系和能量
语义仍待验证。五个默认显示的最近行程实体：秒时长、UTC开始/结束时间、服务端最高速度、
总距离/总时长平均速度。可在实体界面逐个禁用；无累计统计类、无大对象属性、
不会额外查询详情。时间含糊/未来结束时间保持未知，duration与起止跨度冲突时
总平均速度保持未知。历史查询通过下文的响应Actions提供。

有有效时间的行程按结束/开始时间选择最近一条，不依赖服务器行序；旧响应无时间时保留“最近返回”兼容值。月汇总完整性未知，不因20条返回就声称全部行程。

## 历史行程查询 Actions

提供 `ninebot.get_trips` 与 `ninebot.get_trip_detail`，使用必填车辆 `device_id`
和响应变量，不生成历史行程实体。默认不返回轨迹；位置选项与 `include_track`
须同时开启。详情补充最多五条，分页仅针对本次云端返回集合；完整性未知。
轨迹可能进入自动化跟踪或变量，请按需要请求。
参数、响应与自动化示例见 [历史查询 Actions 契约](docs/v2x-历史查询Actions契约.md)。

## 可选骑行事件

骑行事件实体默认禁用。启用后，云端返回已确认travel_id、过去的起止时间与
一致正时长时可发送completed；新ID本身不足以触发事件。启动/重新启用先建立
基线，不回放历史。属性只含简短行程摘要，没有GPS、轨迹、samples或raw JSON。

云端分页/上传延迟未知，因此这是尽力发现的云端结束报告。30分钟迟到窗口与
24小时缺口重建基线是本地策略。写盘确认先于发送，崩溃/取消可能漏一次通知，
不承诺exactly-once或完整历史补发。详情见[骑行事件契约](docs/v2x-骑行事件契约.md)。

控制诊断分别列出本地发送条件、上游支持/权限事实及动作语义证据，显示具体阻止条件。
显式启用并允许车辆后由云端最终鉴权，不伪造允许权限；见[当前控制契约](docs/v2x-云端鉴权控制与实测契约.md)。下方旧阶段描述保留当时行为。

## 图片、位置和请求依赖

标准GPS tracker自然参与HA Map/Zones；撤销位置选项后不再展示坐标，
不做未知坐标系转换。车型图片默认显示，只接受已审核的公开HTTPS来源，
去除不透明签名、拒绝跨来源跳转；URL不变时保留HA图片缓存。未知来源保持
不可用，尚未验证所有车型图片。实体ID与存储schema保持不变。
详见[Phase 8契约](docs/v2x-图片位置与请求依赖契约.md)。

## 2.0.0b9 无效实体清理

按本轮明确要求，首次成功加载后自动清理当前条目独占车辆设备下、已确认无等价
数据源的旧 GSM/地址/续航估算/能耗计数实体，以及不可操作的 Lock 和无用途的满电
续航参数；不再创建占位实体。有效电量、续航、锁定二元状态、用户命名及有意义的
估算模型身份保留，不把暂时无数据当作删除理由，不清理其它条目或自建实体。
通过 HA 公共注册表 API 清理，不编辑 recorder SQL；旧自动化引用需改为有效实体。
升级前备份。本轮开发期间未修改生产HA。

鸣笛/座桶名称取消“实验”前缀，并补充规范图标。本清理版本尚未改变控制发送
策略，不宣称已经恢复实车操作；后续独立阶段处理直接对应ninecli的启动/关闭
按钮、控制门禁及错误回读。

## 2.0.0b10 正常实体可见性

普通/AI续航、最近行程距离/时长/起止时间/速度和车型图片作为正常功能默认显示。
成功首刷后，通过 HA 公共 registry API 启用此前由集成默认禁用的这些实体，
仅匹配当前条目独占、仍在账号列表中的车辆和明确身份。用户手动禁用、自定义名称
和实体 ID 不变。GPS、骑行事件、控制、估算和原始诊断保持各自显式启用策略。
最近行程共用既有行程刷新周期，不额外请求详情。

## 2.0.0b11 原生车辆缓存修复

车辆发现改为固定版本 ninecli 的 `--json vehicles`，同时生成电池/控制路由必需的
`vehicles.json` 业务线路缓存；仅调用 REST `/vehicles` 无法准备此缓存。每次发现
仍为单一列表操作，不额外重复周期查询。原生命令和 REST 共用有界队列与串行锁，
刷新前停止旧 serve，原生更新缓存/token 后按需重新启动。密码仍仅通过本机
鉴权 HTTP 请求体登录，不进入 argv；CLI stderr 不导出，不按错误字符串猜鉴权。

新客户端在隔离会话副本中成功读取并解析两车 BMS；未修改或升级生产 HA、
未执行真实控制。控制仍受当前权限策略约束。详见[输入输出与缓存契约](docs/v2x-ninecli输入输出与车辆缓存契约.md)。

## 2.0.0b12 控制入口与状态说明

“远程启动／远程关闭”以原生命令按钮提供，不映射成 Lock，不使用实验性名称。
启用控制并允许指定车辆后，自动启用该车此前由集成禁用的按钮；用户手动禁用
始终保留。显示按钮不绕过执行门禁：上游权限未知仍拒绝真实请求。

默认显示的“车辆控制状态”诊断实体说明未配置、未允许车辆、需要认证、数据
过期、能力未确认或被拒绝等原因；四个动作属性仅含固定枚举，无原始JSON/身份/
坐标，不额外保活status/battery/travel轮询。大对象仍使用有界内存和schema诊断。

原生二进制loopback测试核对四种REST控制路由和单次请求；同时纠正缓存边界：
REST控制在无车辆缓存时也会发请求，不同于BMS和CLI缓存路由。全部模拟上游
主动返回服务错误，不代表真实云允许或实车动作成功；本轮真实控制为零。

## 2.0.0b13 原始数据利用与诊断

可选诊断“原始数据摘要”只显示该车有界缓存记录数及四个整数指标，不含账号级
车辆列表、原始值、任意字段名、身份或位置，不增加轮询需求。缓存存在不代表
云端最新或历史完整；审核过的详细schema仍通过下载diagnostics获取。

[当前字段利用表](docs/v2x-当前字段利用与调试摘要.md)汇总五个业务endpoint的
136条已观察路径，补齐非空行程和详情；区分已实现表达、私有runtime和未知语义，
候选别名不冒充真实已观察字段。

## 2.0.0b14 状态归属与原生加密验收

status明确返回的sn须匹配请求车辆，错误身份不会覆盖raw/telemetry/成功时间。
缺失/null仍支持；错误局限于status组，不清除登录，旧有效值仍受原TTL限制。

临时native测试副本使用一次性测试公钥，通过完整加密模拟验证控制接受/拒绝，
全部上游loopback、原binary和生产HA不变。不是实车控制证明，不放宽未知权限
门禁。见[新契约](docs/v2x-原生控制加密与状态归属契约.md)。

## 2.0.0b15 云端鉴权控制

覆盖b7–b14的未知权限发送门禁：显式启用并允许车辆，且认证/数据有效、无已知
拒绝时，可发送鸣笛、开座桶、启动和关闭命令。未知不改成允许，不自动重试；
中英诊断状态明确为“可发送命令”，不是车辆已经完成动作。

获得本轮授权后，在生产会话临时副本上对一辆车每种命令各尝试一次，均返回
HTTP200、ok=true、空data；四次回读成功，但选定电源/锁状态没有变化，不能
宣称物理效果已验证。生产HA文件未改动，临时进程/目录已清理。选定空响应
fixture可离线重放，不重复试车。详见[实测与字段契约](docs/v2x-云端鉴权控制与实测契约.md)。

## 2.0.0b17 控制结果与回读

车辆移除或跳过查询不再被当作回读成功，已完成的命令前manual查询不代替
命令后读取。非认证命令错误后最多协调一次status，不重发命令；即使GET成功，
原命令结果仍为未知。认证失败、取消和卸载停止额外I/O。

诊断仅内存保留每车每动作最近调用的分类与时间，全局最多64条、卸载清空；
接口接受、结果未知、回读失败分开，不保存响应/身份/位置/异常原文。没有
新实体或周期请求；本阶段完全离线，b15物理效果与生产安装限制仍适用。
详见[结果与回读契约](docs/v2x-控制结果与状态回读契约.md)。
