2026-10-03；分支 `refactor/ninecli-v2`；开发进行中，尚未合入 main 或创建预发布。

原三份审阅报告描述固定基线和设计建议，不代表当前重构代码已经通过全部验收。

已经实现：

- 固定依赖 ninecli0.1.7，管理受随机Bearer认证的loopback REST子进程。
  假凭据验证了 `/auth/login` 请求体到达本地模拟Passport `/v6/user/login`；
  没有向官方发送真实新密码。无认证请求为401，密码不进入argv，错误正文不记录。
- 类型化不可变领域快照与纯解析器，严格区分缺失、零、无效数值及不支持。
- 会话候选验证与正式提交分离，私有权限、原子journal、备份和回滚；原fork会话复制导入。
- 按车/数据组新鲜度、失败隔离、串行轮询、刷新合并、跨月回退和生命周期清理。
- UI配置、同账号重认证、reconfigure、选项、typed runtime与双来源离线迁移。
- SOC、续航、开关、BMS、行程、可选位置/图片、估算、参数和模拟控制路径。
- 旧估算与无等价数据的实体保留身份/历史，不更新为不同口径数据。
- 同口径重复传感器身份保留值；身份冲突通过Repair提示，不删除注册表。
- 白名单diagnostics，中英文界面/说明、许可说明与CI定义。

实现选择：

1. 采用serve以避免密码argv暴露，取代报告中仅CLI stdout包装的候选方案。
   本地HTTP不是公开服务，同权限进程仍属于本地信任边界；不声称解决所有本机秘密观察。
2. `ec`、`charging_power`仍无独立单位证据，只作默认关闭的无单位诊断；不创建Wh/W统计。
3. 行程月合计不使用未经证实的单调累计state_class；最后行程表示第一条返回记录，默认关闭。
4. 坐标展示需明确选择，坐标系未核验，不自动转换。
5. 实验控制除总开关外还需逐车明确选择，全部测试均为模拟，未验证硬件效果或权限。
6. 新用户需明确设置模型电压/容量。v2估算身份包含generation，旧估算历史不接续。
   SOC模型无法检测没有稳定身份的所有换电，用户换电后需主动重建基线。

本轮新增的关键边界验证：

- 候选目录创建、权限设置、会话导入、提交、finalize的线程取消与清理。
- 同账户事务互斥；运行时reload不误恢复正在提交的journal；真正重启可回滚。
- 重认证reload失败/取消恢复旧会话与配置；finalize已经跨越提交点时保持新配置一致。
- HA reload会结束reauth流程，失败回滚后返回明确abort提示，避免UnknownFlow。
- 卸载取消仍等待子进程/任务清理；控制队列有界，排队动作在卸载时取消。
- 单组/单车失败、认证失效、上月回退失败与控制回读失败分别处理。
- 同功能A/B实体冲突保留两份传感器值、身份和历史并生成Repair。
- v1迁移采用entry派生的稳定目标目录，metadata更新中断后重试不产生多份孤立目录。
- 无效旧账户身份不升级配置，提供脱敏Repair；候选路径、符号链接与journal格式校验。
- 重启/重新启用估算时保留累计量而清除基线；本轮BMS更新后才采样，未知样本不输出假零。
- 旧vehicle_lock_raw保持0锁定/1解锁，App反向编码仅在adapter层转换。
