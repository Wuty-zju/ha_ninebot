# 长期开发索引与归档规则

> 历史归档：保持原版本/证据范围，不继续追加。现行行为先读[CURRENT_STATE](../../agent/CURRENT_STATE.md)和对应主题contract，不能直接执行本文旧goal或“未来”清单。

本页只定义资料治理；当前事实见[CURRENT_STATE](../../agent/CURRENT_STATE.md)，主题入口见
[MAP](../../agent/MAP.md)，完整目录与覆盖关系见[catalog](../../agent/catalog.json)。不再维护第二份当前功能表。

| 资料角色 | 唯一职责 | 更新方式 |
|---|---|---|
| current_state | 接手时的实现/发布/证据状态 | 重大实际变化更新，不复制聊天 |
| current_guide | 操作、导航、组织、交接 | 保持短；指向主题，不粘贴长附录 |
| dated_contract | 形成时的实现规则 | 保留版本；后续覆盖在页首与catalog注明 |
| research | 理由、候选schema、未确认语义 | 记录固定commit/证据门槛，不冒称实现 |
| historical_baseline | 初始重构/旧阶段报告 | 保留原路径与日期，不自动重执行旧goal |
| version_chronicle | 按版本的实施事实 | 追加实际结果/skip，不改写旧测试结果 |
| template | 独立任务或交接结构 | 只作模板，不表示该任务已发生 |

1. 公共docs使用仓库内相对链接；新文档必须进入catalog。大矩阵只保留一个维护位置，研究报告用链接加增量更正。
2. 原始未脱敏资料留本地private/samples；公开fixture需标recorded/synthetic与来源边界。哈希证明完整性，不证明字段语义。
3. 固定报告逻辑归档并保持既有GitHub路径；不为搬目录建立大量空跳转页。已完成阶段在CURRENT_STATE定位，不修改历史“当时未完成”的正文。
4. 同主题冲突先看明确覆盖关系，再核对源码/测试；未知单位、CRS、权限继续待验证。不得将NinePlus heuristic升级成协议事实。
5. 公共evidence新增/变化后生成evidence-index再核验；原始采集hash和旧发布记录不覆盖。私有索引不混入coverage/Release输出。
6. 发布依据精确main SHA、实际CI与[Releases](https://github.com/Wuty-zju/ha_ninebot/releases)；草稿、旧测试、HTTP接受各有不同边界。
7. 任务状态只写本地handoff；实现理由写contract，避免三处同时维护“下一步”。过期临时工具归档，不自动运行。

操作细节和长期维护频率见[工作区组织方案](WORKSPACE_ORGANIZATION.md)与[工作流](../../agent/WORKFLOW.md)。
