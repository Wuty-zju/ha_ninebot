# 安装与日常使用

[English](guide.md) · [文档入口](README.md) · [历史与地图](history_zh.md)

## 环境要求

- Home Assistant **2026.1.0 及以上**，能够访问九号云服务。
- 官方 App 中可以看到车辆的九号账号。
- 兼容固定运行依赖的 64 位主机或容器；不支持 ARMv7/32 位。
- 推荐通过 HACS 安装。这是自定义集成，不是 Supervisor 应用/加载项，也不是 HA Core 内置集成。

当前连接已在中国区 App 服务验证；其他服务地区有待验证。

当前 2.0 候选版为 **v2.0.0rc2**；升级前请备份完整 HA 配置和私有存储。

### 刷新速度

在选项中选择**极快、更快、均衡（默认）、更慢、极慢**。下表为目标周期，单位秒，每辆车独立根据状态调整。状态包包含主电池电量、续航、锁、充电、ACC和位置；电池包包含BMS数据；行程读取当前月份的摘要和列表。

| 档位 | 停车：状态／电池／行程 | 充电：状态／电池 | ACC活跃：状态／电池／行程 |
|---|---|---|---|
| 极快 | 15 / 30 / 300 | 5 / 10 | 2 / 10 / 30 |
| 更快 | 30 / 30 / 600 | 10 / 15 | 5 / 15 / 60 |
| 均衡 | 60 / 60 / 600 | 15 / 30 | 10 / 30 / 120 |
| 更慢 | 120 / 180 / 1200 | 30 / 60 | 30 / 60 / 300 |
| 极慢 | 300 / 600 / 1800 | 60 / 120 | 60 / 180 / 600 |

车辆资料每小时更新。提高速度会增加云请求，实际仍受共享准入、排队和服务端退避约束。状态与BMS是不同请求；单独需要电量或位置时共享状态包。旧的自定义数字周期保持不变，直到主动选档。仅调整刷新速度会保留当前会话、本地档案和实体身份；功能、隐私及认证变化保留原来的重载行为。

## 通过 HACS 安装

1. HACS 右上角三点菜单 → **自定义仓库**。
2. 添加 `https://github.com/Wuty-zju/ha_ninebot`，类型选择 **集成 Integration**。
3. 打开 **Ninebot**，选择 **v2.0.0rc2**（必要时开启预发布显示）并下载。
4. 按提示重启 HA。文件版本更新不代表运行中的集成已加载新版。
5. **设置 → 设备与服务 → 添加集成 → Ninebot**。

[打开 HACS 仓库](https://my.home-assistant.io/redirect/hacs_repository/?owner=Wuty-zju&repository=ha_ninebot&category=integration) · [添加 Ninebot](https://my.home-assistant.io/redirect/config_flow_start/?domain=ninebot)

链接打开你配置的 HA，不会安装 HACS 本身。当前通过**自定义仓库**分发，不宣称已进入 HACS 默认列表。

## 手动安装

下载所选 [GitHub Release](https://github.com/Wuty-zju/ha_ninebot/releases) 的 `ninebot.zip`，将包内文件解压到 `<config>/custom_components/ninebot`，重启后添加集成。旧版本若没有此附件，则从源码包中复制 `custom_components/ninebot`。不要把整个开发仓库复制进配置目录，也不要混合不同版本文件。

所有运行所需 Python、翻译、品牌和卡片资源都随集成目录分发，无需手动安装独立服务、另一个卡片包或仓库根脚本。

## 添加账号与车辆

使用账号和密码登录。短信登录暂不可用，添加账号、重新认证和重新配置均不显示该入口。密码用于认证，不保存在 ConfigEntry，也不作为进程参数传递。验证成功后，新版HA自动进入账号配置，旧版HA在同一向导中选择车辆功能。会话/token 文件依然敏感，须保护本地配置与备份。

每个配置条目代表**一个账号**，会话与历史库独立；另一个账号通过新增条目添加。车辆在账号下自动发现，同一辆共享车辆在不同账号下可以有独立的 HA 表示。

条目标题使用实际上报的 `用户名：账号`，缺失部分省略。地区字段含义尚未确认，暂不显示；用户自定义标题保留。外围分组标题由 HA 按集成类型生成，不修改全局前端翻译。

凭据失效使用**重新认证**；重新配置仍是同一个账号，新增账号应添加新条目。旧账号缺用户名时，成功设置期间最多补充一次展示元数据，不循环查询用户名。

## 实体与数据

可用信息取决于车型、权限与云端上报。普通实体随对应功能启用并显示；调试诊断随调试开关，事件和日历另有独立选项。保留用户已有的禁用／隐藏选择。

| 分类 | 信息 | 含义与限制 |
|---|---|---|
| 车辆 | 主电池电量、精准/预估/AI 续航、充电、上电、ACC、电池存在、智能服务 | 三种续航分别取值；AI 续航属诊断。ACC 开启不等于正在移动。 |
| 主电池 | 电压、温度、循环及支持、充电功率、健康评分、电池组身份/数量/类型、Find My 支持 | 主电池电量代表动力电池；健康评分不是 SOH，0 可表示不支持。 |
| 通信 | 应急通信电池电量 | 独立百分比，不替代车辆的主电池摘要。 |
| 位置与图片 | 设备位置 tracker、车辆图片 | 需要两个有效且新鲜的坐标，不做未经验证的坐标转换；图片位于诊断。 |
| 骑行 | 今日/昨日/本月、最近行程、单次月列表覆盖率 | 各指标分别核验完整性，缺证据不假装为 0。 |
| 历史同步 | 状态、月份扫描进度、已发现详情保存进度、最近成功时间 | 统计范围不同；详情 100% 不代表已发现全部云历史。 |
| 控制 | 车辆锁/座桶锁与保留的远程按钮 | 受控制开关、允许车辆、权限及归属检查约束。 |
| HA 原生能力 | 行程日历、车辆／行程事件、查询 Action、统计导入 | 不为每趟历史或每个 GPS 点创建实体。 |

时长保存原生秒值，使用 HA 原生换算，默认显示 **h、四位小数**。里程/续航和 Wh/km 默认一位小数；能耗与最高速度默认整数。显示舍入不改变归档原值，HA 用户自定义单位/精度优先。额定 V/Ah 得到的 kWh 是规格，不是实测容量或健康。

只有循环支持明确为不支持时，次数才显示不支持；未知仍未知。总里程缺报显示未上报，不猜数值/单位。英中是主要文档语言，实体/设置标签另覆盖多种语言，部分长说明回退英语。

历史详情同步关闭时，已启用的今日／昨日统计仍可按需补齐被截断的当月行程列表，每账号每轮最多一页，共享历史请求额度、暂停和退避；月初必要时包括相邻月份。完整本地索引直接复用，不下载详情／轨迹，也不自动开启全历史扫描。

## 配置选项

**设置 → 设备与服务 → Ninebot → 配置**。

| 选项 | 默认与范围 | 作用 |
|---|---|---|
| 刷新速度 | 均衡；五档可选 | 逐车逐组根据充电／ACC调整。旧自定义值在主动选档前保留；仅换档不重载账号。 |
| 精确位置 | 开启 | 允许位置展示与轨迹响应，保留已有关闭选择；不会新增一次高精定位请求。 |
| 车辆事件（Beta） | 开启 | 同时控制行程上报/修订/完成与车辆状态转换事件，关闭保留身份，重新开启不重放旧事件。 |
| 行程日历（Beta） | 新账号关闭，保留已有选择 | 关闭不删历史，也不关闭 tracker。 |
| 自动同步历史详情（Beta） | 新账号关闭，保留已有选择 | 保存私有历史详情/轨迹并启用预算化采集，注意位置和备份隐私。 |
| 自动扫描历史行程（Beta） | 新账号关闭，保留已有选择 | 保存详情开启时，首次发现与后续增量持续执行。 |
| 历史空间（Beta） | 每账号 100 MiB；32–2048 MiB | 超额暂停写入，已有内容仍可读取；降低上限不删历史。 |
| 历史请求预算（Beta） | 每账号每小时 60；0–120 | 月份与详情共享逻辑请求预算；不是向官方申请权限，传输内部重试不计入此逻辑数。数字输入框填写0则取消每小时配额（不推荐），仍保留请求串行与云端退避。 |
| 控制与允许车辆 | 新账号开启/登录时核验的全部车辆 | 位于页面顶部，通过原生多选下拉框选取该账号的一辆或多辆车；启用控制须至少选择一辆，关闭保留选择。历史同步权限单独管理。 |
| 保留本地历史数据库（Beta） | 开启 | 移除账号后保留历史，重新登录同账号接回。 |
| 额定参数 | 关闭 | 额定电压/容量默认留空，可分别填写或清空；两项齐全才计算额定能量；不恢复退役的低信电量估算。 |
| 调试模式 | 关闭 | 有界当前解析信息，不额外轮询、不公开完整 raw。 |

默认策略下，充电时状态／电池目标为15／30秒；ACC活跃时状态／电池／行程为10／30／120秒。充电切换、外部解锁和停止会开启有限观察窗口。ACC表示活跃，单独上电不能证明车辆移动；旧自定义周期在选择档位前保留原行为。

停止后最多补查六次当前月摘要，复用在途读取，不下载旧行程详情。锁确认及后续回读保持原规则，不自动重复控制命令。

周期读取采用本地准入保护：每账号每秒1次、突发3次，全局每秒2次、突发6次；请求过多时公平延期。这是本地调度策略；首次初始化、主动查询、控制及独立预算的历史同步沿用各自有界通道。服务器重试要求优先，诊断可区分目标间隔、实际间隔、排队耗时与延期原因。

按需求请求，各组独立 freshness/退避，合并相同在途读取；重载/卸载回收任务。读取缓存不会伪装成新测量。

## 控制与反馈

车辆解锁请求远程开启，上锁请求远程关闭；车辆/云端决定移动或 P 档要求。集成不猜测移动状态来禁用关闭。座桶仅远程解锁，上锁需本地完成；按钮与 Lock 走同一执行器。

每次明确操作只发一次命令，不自动重放。十五秒内最多十六次查询目标状态，再以 10/20/25 秒短期观察自动回锁；30 秒内或错误/卸载/新操作时结束。按新云端观测确认目标状态，结果区分待确认／失败／未确认。新指令可替换之前的确认观察；同一物理车辆仅在命令发送期间互斥。

观察到座桶解锁后，Lock 实体至少显示解锁五秒，期间继续查询状态。“上报锁舌状态”属性及车辆状态事件始终保留真实上报；五秒后，Lock 按最新有效锁舌状态显示。另开最多六十秒的状态观察：前十五秒约每秒查询，之后在第20/30/45/59.9秒查询。慢响应错过的时点会跳过，不集中补发。

锁舌复位时座桶盖仍可能打开。现有数据没有经核实的独立开盖／关盖字段，因此暂不推断盖子位置或创建“座桶状态”实体。五秒显示窗口不代表盖子已打开。新操作、卸载、认证失效、限流或读取错误会结束后续观察。

历史同步与暂停位于设备诊断区域；同步按钮也会恢复已暂停的任务。运行、暂停及等待额度通过图标与同步状态属性显示。同步状态、最近成功时间和原始解析视图仅在调试模式开启时显示；日历仍由独立开关控制。诊断分类不等于Recorder排除，可按需配置Recorder过滤。

| 问题 | 先检查 |

| 安装后找不到集成 | 目录、domain、运行架构，按提示重启。 |
| 首次升级持续初始化 | 旧库校验和整合先于设置完成，多个库可能需要数分钟。检查日志最新时间并等待迁移完成；若重复失败，保留错误堆栈和诊断。 |
| 登录失败 | 官方 App 与服务地区，重新认证；不要公开凭据/token。 |
| 额定参数选车报错 | 确认新版已加载，关闭并重新打开表单，选择当前发现的车辆。 |
| 今日/昨日未知 | 配置完成及跨天会及时刷新；缺失列表或指标仍需补证据。同周期已验证值可跨短暂断网保留，见[覆盖与统计](history_zh.md#覆盖与统计)。 |
| 骑行/车辆事件未知 | 等待基线后的新行程上报、修订、稳定完成或已知状态转换；历史导入和断线恢复不补发。详见[事件语义](history_zh.md#行程摘要与车辆事件)。 |
| 等待请求预算 | 查看 next_request_at/retry_at/sync_phase、暂停/认证/容量，不反复全量扫描。 |
| 日历显示“无当前行程”/off | 历史日历没有当前活动事件，并非停用。请在HA日历中浏览已保存日期；账号选项才控制启用/关闭。 |
| Custom element not found | [注册卡片模块](history_zh.md#添加历史地图)，刷新浏览器。 |
| 无轨迹/只有单点 | 已存详情、坐标开关/权限、服务器质量；简化数据不能还原已丢路线。 |
| 存储 Repair | 留住文件，读[校验与恢复](history_zh.md#校验与恢复)，不要删除库/registry 消除提示。 |
| HA 提示未测试自定义集成 | 第三方集成标准提示，不屏蔽。 |

## 隐私、备份与移除

位置默认开启，详情保全可能保留精确路线；私有库与 HA 备份均包含位置记录，即使某次响应没带坐标。自动化 trace 可能保存请求的响应。诊断只输出审核后的 schema/状态，不包含凭据、身份或轨迹，分享前仍需检查。

底图需单独开启并会联系外部服务，见[地图隐私](history_zh.md#地图隐私与单位)。保护会话目录和备份，主机同用户/高权限进程仍在本地信任边界内。

**保留本地历史行程信息数据库（Beta）**默认勾选。移除账号会停止任务，保留行程、详细轨迹与恢复证据；重新添加同一已认证账号后接回原库，按已有选项继续同步。取消勾选后，下次删除账号会删除该账号的受管归档及恢复副本。无法识别的文件会保留并提示 Repair；该选项不会删除 Recorder 历史。不手工修改运行中的库或 registry，升级/降级见[迁移指南](migration_zh.md)。




## 导出和导入历史数据库

在账号的**配置**表单中勾选**导出或导入历史数据库（Beta）**并提交，下一步菜单提供**导出数据库**和**上传并导入数据库**。这些操作仅限 Home Assistant 管理员。

- **导出：**选择已加载账号下的一个或多个车辆，点击有效期十分钟、绑定当前管理员的下载链接获取 ZIP。文件名包含 UTC 时间、账号／车辆数、范围摘要和导出 ID；清单另含 schema、数量和时间范围。包内包含一致的 SQLite 快照、历史源证据与版本化 SHA256 清单，不包含密码或登录会话。
- **导入：**先登录包内所有账号，再上传 ZIP（或受支持旧格式的单个 SQLite 数据库）、选择车辆并确认备份和合并。写入前校验账号归属、schema、引用、原始响应哈希及行程身份。新简化响应不会覆盖更完整的旧轨迹；重复导入去重。
- 每个账号的全部选中来源在同一事务内合并。校验提交成功后删除临时恢复快照；失败时保留恢复点。后续账号失败时，已完成账号仍保留，可安全重试同一包。现有选项、实时授权与正在运行的同步任务不被替换。

归档包是私密 GPS 记录，不是诊断文件；请安全传输，集成不对包加密。上传限制为压缩后100 MiB、解压后512 MiB，最多16个账号。旧包每账号最多16个来源快照会实际合并，不再长期保留为多个数据库；新导出每账号只有一个 SQLite。独立历史原始响应纳入主库并计入容量，校验合并成功的旧迁移／导入副本会自动清理；失败或无法识别的文件保留待检查。升级前备份完整 HA 配置，迁移或回退另保留外部导出包。

## 连接中断

云端或车辆发现暂时异常时，保留已验证的同周期行程统计和本地历史。实时读数保留真实响应时间，过期后如实显示不可用。集成会自动重试恢复，无需删除并重新添加账号；车辆未在发现结果中出现时，其控制保持暂停，等待重新核验。可下载集成诊断查看发现重试、连接冷却及实际状态间隔。配置的轮询周期是目标，云端故障和限流可能延迟新读数。
