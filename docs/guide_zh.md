# 安装与日常使用

[English](guide.md) · [文档入口](README.md) · [历史与地图](history_zh.md)

## 环境要求

- Home Assistant **2026.1.0 及以上**，能够访问九号中国区 App 服务。
- 官方 App 中可以看到车辆的九号账号；其他服务地区尚未验证。
- 精确固定的运行依赖支持的 64 位平台；不支持 ARMv7/32 位。有对应 Linux/macOS/Windows wheel 不等于所有主机或容器架构均已认证。
- 推荐通过 HACS 安装。这是自定义集成，不是 Supervisor 应用/加载项，也不是 HA Core 内置集成。

2.0 系列目前为 **prerelease**。厂商服务变化可能影响可用性；升级前备份完整 HA 配置和私有存储。

## 通过 HACS 安装

1. HACS 右上角三点菜单 → **自定义仓库**。
2. 添加 `https://github.com/Wuty-zju/ha_ninebot`，类型选择 **集成 Integration**。
3. 打开 **Ninebot**，选择需要的 2.0 预发布版本并下载；必要时在版本选择中开启 beta/prerelease。
4. 按提示重启 HA。文件版本更新不代表运行中的集成已加载新版。
5. **设置 → 设备与服务 → 添加集成 → Ninebot**。

[打开 HACS 仓库](https://my.home-assistant.io/redirect/hacs_repository/?owner=Wuty-zju&repository=ha_ninebot&category=integration) · [添加 Ninebot](https://my.home-assistant.io/redirect/config_flow_start/?domain=ninebot)

链接打开你配置的 HA，不会安装 HACS 本身。当前通过**自定义仓库**分发，不宣称已进入 HACS 默认列表。

## 手动安装

下载所选 [GitHub Release](https://github.com/Wuty-zju/ha_ninebot/releases) 的 `ninebot.zip`，将包内文件解压到 `<config>/custom_components/ninebot`，重启后添加集成。旧版本若没有此附件，则从源码包中复制 `custom_components/ninebot`。不要把整个开发仓库复制进配置目录，也不要混合不同版本文件。

所有运行所需 Python、翻译、品牌和卡片资源都随集成目录分发，无需手动安装独立服务、另一个卡片包或仓库根脚本。

## 添加账号与车辆

支持密码和两步短信登录。密码用于认证，不保存在 ConfigEntry，也不作为进程参数传递。短信流程有离线回归覆盖，实机验证仍待补充。会话/token 文件依然敏感，须保护本地配置与备份。

每个配置条目代表**一个账号**，会话与历史库独立；另一个账号通过新增条目添加。车辆在账号下自动发现，同一辆共享车辆在不同账号下可以有独立的 HA 表示。

条目标题使用实际上报的 `用户名：账号[地区]`，缺失部分省略。`bj` 等路由值不证明住址或车辆位置；用户自定义标题保留。外围分组标题由 HA 按集成类型生成，不修改全局前端翻译。

凭据失效使用**重新认证**；重新配置仍是同一个账号，新增账号应添加新条目。旧账号缺用户名时，成功设置期间最多补充一次展示元数据，不循环查询用户名。

## 实体与数据

可用信息取决于车型、权限与云端实际返回。创建的实体默认启用且可见，保留用户已有的禁用/隐藏选择；对应功能仍受配置开关控制。

| 分类 | 信息 | 含义与限制 |
|---|---|---|
| 车辆 | 主电池电量、精准/预估/AI 续航、充电、上电、ACC、电池存在、智能服务 | 三种续航分别取值；AI 续航属诊断。ACC 开启不等于正在移动。 |
| 主电池 | 电压、温度、循环及支持、充电功率、健康评分、电池组身份/数量/类型、Find My 支持 | 主电池电量代表动力电池；健康评分不是 SOH，0 可表示不支持。 |
| 通信 | 应急通信电池电量 | 独立百分比，不替代车辆的主电池摘要。 |
| 位置与图片 | 设备位置 tracker、车辆图片 | 需要两个有效且新鲜的坐标，不做未经验证的坐标转换；图片位于诊断。 |
| 骑行 | 今日/昨日/本月、最近行程、单次月列表覆盖率 | 各指标分别核验完整性，缺证据不假装为 0。 |
| 历史同步 | 状态、月份扫描进度、已发现详情保存进度、最近成功时间 | 统计范围不同；详情 100% 不代表已发现全部云历史。 |
| 控制 | 车辆锁/座桶锁与保留的远程按钮 | 需主动启用、允许车辆、权限及归属检查。 |
| HA 原生能力 | 行程日历、骑行事件、查询 Action、统计导入 | 不为每趟历史或每个 GPS 点创建实体。 |

时长保存原生秒值，使用 HA 原生换算，默认显示 **h、两位小数**。里程/续航和 Wh/km 默认一位小数；能耗与最高速度默认整数。显示舍入不改变归档原值，HA 用户自定义单位/精度优先。额定 V/Ah 得到的 kWh 是规格，不是实测容量或健康。

只有循环支持明确为不支持时，次数才显示不支持；未知仍未知。总里程缺报显示未上报，不猜数值/单位。英中是主要文档语言，实体/设置标签另覆盖多种语言，部分长说明回退英语。

## 配置选项

**设置 → 设备与服务 → Ninebot → 配置**。

| 选项 | 默认与范围 | 作用 |
|---|---|---|
| 状态周期 | 120 秒；30–3600 秒 | battery/travel 独立为 600 秒，profile 为 3600 秒；不是云端新鲜度保证。 |
| 精确位置 | 开启 | 允许位置展示与轨迹响应，保留已有关闭选择；不会新增一次高精定位请求。 |
| 行程日历 | 开启 | 关闭不删历史，也不关闭 tracker。 |
| 保存行程详情 | 新账号开启，保留旧账号选择 | 保存私有历史详情/轨迹并启用预算化采集，注意位置和备份隐私。 |
| 自动历史同步 | 新账号开启，保留旧选择 | 保存详情开启时，首次发现与后续增量持续执行。 |
| 历史空间 | 每账号 100 MiB；32–2048 MiB | 超额暂停写入，已有内容仍可读取；降低上限不删历史。 |
| 历史请求预算 | 每账号每小时 30；1–60 | 月份与详情共享逻辑请求预算；不是向官方申请权限，传输内部重试不计入此逻辑数。 |
| 控制与允许车辆 | 关闭/空列表 | 显式授权车辆控制；历史同步权限单独管理。 |
| 额定参数 | 关闭 | 可选额定电压/容量与额定能量；不恢复退役的低信电量估算。 |
| 调试模式 | 关闭 | 有界当前解析信息，不额外轮询、不公开完整 raw。 |

按需求请求，各组独立 freshness/退避，合并相同在途读取；重载/卸载回收任务。读取缓存不会伪装成新测量。

## 控制与反馈

车辆解锁请求远程开启，上锁请求远程关闭；车辆/云端决定移动或 P 档要求。集成不猜测移动状态来禁用关闭。座桶仅远程解锁，上锁需本地完成；按钮与 Lock 走同一执行器。

每次明确操作只发一次命令，不自动重放。约 0/2/5 秒查询目标状态，再以 10/20/25 秒短期观察自动回锁；30 秒内或错误/卸载/新操作时结束。云状态不等于物理完成保证，待确认/失败/未确认分开。同辆物理车辆的冲突操作返回忙，不排队稍后执行。

## 常见问题

| 问题 | 先检查 |
|---|---|
| 安装后找不到集成 | 目录、domain、运行架构，按提示重启。 |
| 登录失败 | 官方 App 与服务地区，重新认证；不要公开凭据/token。 |
| 额定参数选车报错 | 确认新版已加载，关闭并重新打开表单，选择当前发现的车辆。 |
| 今日/昨日未知 | [覆盖与统计](history_zh.md#覆盖与统计)：部分月、缺指标或冲突不支持可靠日统计。 |
| 骑行事件未知 | 等待启动 baseline 之后新的稳定完成事件，不等于最近历史行程结束时间。 |
| 等待请求预算 | 查看 next_request_at/retry_at/sync_phase、暂停/认证/容量，不反复全量扫描。 |
| Custom element not found | [注册卡片模块](history_zh.md#添加历史地图)，刷新浏览器。 |
| 无轨迹/只有单点 | 已存详情、坐标开关/权限、服务器质量；简化数据不能还原已丢路线。 |
| 存储 Repair | 留住文件，读[校验与恢复](history_zh.md#校验与恢复)，不要删除库/registry 消除提示。 |
| HA 提示未测试自定义集成 | 第三方集成标准提示，不屏蔽。 |

## 隐私、备份与移除

位置默认开启，详情保全可能保留精确路线；私有库与 HA 备份均包含位置记录，即使某次响应没带坐标。自动化 trace 可能保存请求的响应。诊断只输出审核后的 schema/状态，不包含凭据、身份或轨迹，分享前仍需检查。

底图需单独开启并会联系外部服务，见[地图隐私](history_zh.md#地图隐私与单位)。保护会话目录和备份，主机同用户/高权限进程仍在本地信任边界内。

移除账号会关闭任务，仅清理识别的库/journal；异常文件/恢复副本可能保留并提示 Repair，不做广泛删除。先备份，不手工改 `.storage`、实体 registry 或运行中的库。升级/降级见[迁移指南](migration_zh.md)。
