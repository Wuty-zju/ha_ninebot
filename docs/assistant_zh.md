# Ninebot Assistant

[English](assistant.md) · [文档](README.md) · [历史行程与地图](history_zh.md)

本文适用于 **2.2.9 预览版**。其他版本请查阅 [v2.2.0 正式版指南](https://github.com/Wuty-zju/ha_ninebot/blob/v2.2.0/docs/assistant_zh.md)或 [v2.2.8 预览版指南](https://github.com/Wuty-zju/ha_ninebot/blob/v2.2.8/docs/assistant_zh.md)。

通过 Home Assistant 原生 LLM API 和 MCP Server，兼容的对话宿主可以读取授权车辆的本地数据、查询带来源的帮助，并申请补齐行程。只读查询和需人工审批的任务分别授权。

## 升级至统一的 Ninebot API

2.2.9 预览版移除了 **Ninebot tasks**（`ninebot_tasks`）。用管理员身份访问原地址 `/api/mcp/ninebot_tasks` 会收到 404，不会跳转。

| 宿主目前的连接方式 | 升级操作 |
|---|---|
| 使用独立的 `/api/mcp/ninebot`，或主地址 `/api/mcp` 已开启**暴露全部 AI 工具** | 沿用原地址，新建会话以发现当前工具。 |
| MCP Server 或对话宿主明确保存了 **AI 工具**列表 | 打开宿主设置，取消勾选 **Ninebot tasks**，保留 **Ninebot** 和其他已选工具，再保存。如果原来只选了旧集合，先核对车辆数据与任务权限，再选择 **Ninebot**。保存的旧 ID 可能导致整组工具无法加载。 |
| 客户端直连 `/api/mcp/ninebot_tasks` | 先核对车辆数据与任务权限，再将地址改为 `/api/mcp/ninebot`。 |

账号会保留原来所选车辆的读取权限。如果旧版已同时启用助手和历史任务并选过车辆，请在 Ninebot 助手选项中选择**审核现有任务权限**，确认时选择**应用逐车任务权限**。确认前，宿主不会看到任务工具，已有申请仍按原审批和执行规则处理。主动撤销已有申请权限会使该账号原授权下的未决申请失效。参阅[历史任务](#可审核的历史任务beta)和[回退步骤](migration_zh.md#在-22-各版本之间更新)。

## 开启方式

1. 从 Marketplace、HACS 或[发行包](https://github.com/Wuty-zju/ha_ninebot/releases)安装 **2.2.9 预览版**，进入需要授权的账号。
2. 原生 Assistant API 使用 **Home Assistant 2026.11+**。普通车辆功能仍维持 **2026.1.0** 最低版本；缺少所需原生 API 时不显示 Assistant 选项。
3. 打开需要授权账号的 **设置 → 设备与服务 → Ninebot → 选项**，勾选**配置 Ninebot 助手**并提交。在**助手访问权限**中选择**为此账号启用助手**及要设置的车辆。助手默认关闭，新发现的车辆也默认无助手权限。远程控制权限单独设置。
4. 在原生 **MCP Server** 集成中，关闭访问全部 LLM API，仅选择 **Ninebot**，保留管理员要求并开启只读模式。按 Home Assistant 支持的认证方式，将 MCP 客户端连接到 `/api/mcp`。
5. 使用有效的管理员身份。每次调用都会复核当前用户、账号开关、车辆归属及所请求操作的权限。

每辆车可分别开放四类数据：**车况**、**汇总统计**、**逐次行程**（包括已保存的详情）和**同步健康**。通用帮助要求存在一辆获准车辆，组合统计排查需有汇总统计、同步健康和帮助权限。只开放汇总统计时，仍可直接使用 `get_statistics`。勾选**编辑另一辆车**可继续设置后一起保存。

使用原生 Conversation/Assist 宿主时，若宿主支持自定义 LLM API 并保留已认证用户 Context，可选择 **Ninebot** API。具体选项和工具支持取决于宿主。Ninebot 不配置模型、模型密钥或额外监听服务。通用 Action 工具与暴露实体属于独立能力；注册 Ninebot Action 本身不会自动启用这些专属工具。

支持提示模板的 MCP 客户端可通过 `prompts/list` 和 `prompts/get` 获取 **Ninebot** 模板，并在客户端的提示入口应用它。仅发现工具不代表客户端已应用这份说明。无论是否支持模板，工具调用始终执行相同的权限校验。

## 核对MCP的API选择

HA 2026.11+ 的主 `/api/mcp` 地址优先使用“暴露全部AI工具”（`all_llm_apis`）。开启时选择当前全部已注册API，包括之后新增的集合；已保存的“AI工具”选择（`llm_hass_api`）不限制该列表。关闭后才使用所选集合。“只读”（`read_only`）过滤此主地址中的工具。

独立地址 `/api/mcp/ninebot` 直接选择已注册的 `ninebot` API，不继承主地址的 API 选择或只读选项。如果希望独立地址和对话宿主都无法为某辆车提交申请，请把该车的任务权限设为**关闭**或**仅预览**。每项新申请均由原申请人在 Home Assistant 另行批准。[原生 MCP 配置选项](https://www.home-assistant.io/integrations/mcp_server/#configuration-options)

## 选择宿主和模型

选择支持 HA 工具调用的宿主。模型可以本地运行，也可以来自云服务。

| 入口 | 如何配置 | 使用方获得什么 |
|---|---|---|
| Assist / Conversation | 在支持工具调用的对话代理中选择 **Ninebot**。 | 宿主读取工具结果，自行组织回答。 |
| 外部 MCP 客户端 | 通过 HA 身份认证连接原生 MCP Server，在 `/api/mcp` 选择 **Ninebot**，或直连 `/api/mcp/ninebot`。 | 使用当前 HA 用户身份的同一套工具与结果。 |
| 自动化 | 把已有的、支持工具调用的 `ai_task` 实体传给 `ninebot.ask`。 | 经核验的工具结果，以及能够生成时附上的格式化答案。 |

原生对话和 MCP 共用 **Ninebot** 集合。读权限完整且历史任务关闭时共有 8 项工具。开放预览后增加 4 项，共 12 项。允许申请、审核服务可用且宿主允许写入时，共 13 项。实际发现和调用仍取决于逐车权限。[HA LLM API](https://contributors.home-assistant.io/core/internals/llm-api/) · [原生 MCP Server](https://www.home-assistant.io/integrations/mcp_server/) · [AI Task](https://www.home-assistant.io/integrations/ai_task/)

## 通过已有AI任务查询

在**开发者工具 → 动作**或自动化里，选定模型实体和 HA 车辆。Action 将原调用用户的身份传入模型任务与业务查询，最多可用八项查询工具，具体取决于该车的读取权限。即使一辆已获授权的车超出了发现列表的前 20 辆，也可直接指定该车。

```yaml
action: ninebot.ask
data:
  ai_task_entity_id: ai_task.your_model
  device_id: your_ninebot_device_id
  question: 这辆车最近上报的主电池电量是多少？
response_variable: ninebot_answer
```

先读 `outcome`。取得 `evidence` 后，读取 `results`，或显示 `{{ ninebot_answer.get('answer', {}).get('text', '') }}`。2.2.8 预览版可以针对单项车况返回数值、单位、来源组、观测时间和新鲜度。中途中断可返回 `partial` 和已重新验权的结果。撤销授权会撤回私有结果。需要选择车辆时，`needs_input` 可同时给出 `next_step.type: select_vehicle`，选定车辆后再查询。

Action 根据工具回执编排回复。帮助节选保留完整来源链接和知识库版本，日期、数量、单位和覆盖范围来自业务代码。可选格式化结果使用 `ninebot-evidence-answer-v1` 并列出引用的请求 ID。32 KiB 的响应空间优先保留完整结构化数据。对话宿主可以自行展示工具结果。

一次 Action 最长运行 180 秒，最多调用四次工具，同一集成同时运行一个 Action 问答。需要支持 `ai_task.async_generate_data(..., llm_api=...)` 的 HA 版本与模型宿主。原生 **Ninebot** 集合可独立使用。

## 查询本地数据

例如：

- “Vehicle A 昨天骑了几趟？”
- “Vehicle A 上个月耗电多少？”
- “Vehicle A 在2026年11月5日骑了几趟？”
- “列出 Vehicle A 11月5日的行程，再查看选中行程的已保存详情。”
- “Vehicle A 当前状态是否新鲜？”
- “历史同步在等待什么？”

有多辆车时，先选定车辆再查询数值。宿主从 `ninebot__get_vehicles` 获取不透明的 `vehicle_ref`；账号、车辆序列号及表示 MCP 客户端来源的 `device_id` 均不能替代它。 应原样复制返回的引用。拒绝访问不能判定配置故障或隐藏车辆是否存在；应核对选中引用与HA权限，也不能用另一辆获准车辆代替问题中的目标。

| 工具 | 参数 | 返回内容 |
|---|---|---|
| `ninebot__search_help` | `query`；可选 `language`（`en` 或 `zh-Hans`）、`include_procedures`（默认 `false`） | 最多三条附引用的公开帮助；指导具体任务时显式请求任务清单。 |
| `ninebot__get_vehicles` | 无 | 已向 AI 授权的车辆引用、显示名称及本地数据能力。 |
| `ninebot__get_vehicle_status` | `vehicle_ref`，可选 `metric`（2.2.8） | 读取一项缓存值及其观测组。省略指标则返回车况和 BMS 概览。 |
| `ninebot__get_statistics` | `vehicle_ref`、`period` | 本地 `today`、`yesterday`、`this_month`、`last_month` 或单个明确业务日期／月份的统计及逐指标覆盖情况。 |
| `ninebot__get_recorded_trips` | `vehicle_ref`、`start_date`、`end_date`；可选 `limit`、`cursor` | 一页按时间倒序排列的本地行程。日期格式 `YYYY-MM-DD`，含首尾最多31天；默认10条，最多20条。 |
| `ninebot__get_trip_detail` | `vehicle_ref`、`ride_id`、`query_month` | 对应车辆及月份中已验证行程的本地标量详情。使用列表返回的行程 ID 和 `YYYYMM` 月份。 |
| `ninebot__get_sync_health` | `vehicle_ref` | 只读查询全档案行程计数、扫描和详情保存进度，以及当前请求节奏。 |
| `ninebot__explain_statistics` | `vehicle_ref`、`period`、`metric`；可选 `language` | 三个本地步骤：周期统计、同步健康、附引用的帮助与统计排查清单。 |

全部工具均读取本地信息。缺失详情需要通过正常的[历史功能](history_zh.md)采集；AI 只读调用不会触发云请求。列表游标可能被消费，应继续使用返回的下一页游标，不反复重放上一游标。一页记录数量不代表整个时间段的行程总数。

从 **2.1.10** 起，`get_statistics` 的 `period` 也接受一个 `YYYY-MM-DD` 日期，例如 `2026-11-05`。日期沿用 Asia/Shanghai，范围从2000年起，不接受未来日期；查询读取已有本地日投影。已验证的空日可返回0，未观测日期保持未知，原四个相对周期继续可用。

从 **2.1.17** 起，`period` 也接受 `YYYY-MM`，例如 `2026-10`。已结束月份取完整自然月，当前月份截至当前业务日；年份从2000年起，不接受未来月份。月统计使用已有服务端月汇总，与每日投影及行程分页小计分别表达。

排查具体数值时，可用 `ninebot__explain_statistics` 指定车辆、周期及一个指标：`ride_count`、`distance_km`、`duration_s`、`energy_wh` 或 `energy_intensity_wh_per_km`。固定流程返回实际统计、同步健康、适用版本的帮助引用与SK05清单。`data.steps`保留各工具结果及观测时间，`quality.partial`表示有步骤失败或未执行。指标原因描述目前的证据，不直接判定根因；此查询不修复数据、不启动云端任务。

从 **2.1.9** 起，行程分页保留每条记录的 `received_at`，并在 `quality.months` 返回最多三个月份的观测摘要，空页也保留这些信息。`query.as_of` 表示本次工具调用时间，`quality.page_as_of` 表示游标各页沿用的选取截止时点，均与档案的实际观测时间区分。固定截止时点不等于冻结整个数据库，也不能证明云端完整性；缺失的观测信息保持 `null`。

## 理解数据依据

**单项读数示例。** 合成样例 `battery_soc_percent: 0` 配合 `quality.metrics.battery_soc_percent.status: available` 表示上报了零电量。相同读数若注明 `stale`，表示较早的观测。缺失或空值保留未知，布尔读数的 `false` 保留原义。该观测组的 `received_at` 给出采集时间。

结果包含业务日期范围、观测时间、单位、指标质量、来源证据及提示。业务日期沿用当前档案契约的 **Asia/Shanghai**，不随浏览器时区变化。 此字段描述档案规则，不能据此推断浏览器设置。工具不按另一时区重新划分日／月统计；界面可将时间戳显示为本地时间，统计仍使用其业务日期边界。

- 已确认没有行程的周期可以返回 **0**；缺失数值为 **null**，附带原因或质量信息。
- 部分覆盖仅代表目前已知记录，不能据此确认完整总量。
- 当前状态可能陈旧；已结束月份的历史事实不会仅因时间久而被判过期。
- 每日里程图与按行程结束日期归属的统计采用不同来源投影，结果会标明依据。
- 最高速度与距离除以时长得出的总平均速度分别表达；未知采样单位保持待验证。
- 未验证的第四列也不能直接标为`mph`、整体平均速度或据此换算。独立的最高速度和距离／时长平均值，不能证明逐点采样列的单位。
- `acc_active` 表示电门状态，不证明车辆移动或正在骑行。`seat_locked` 只表示座桶锁舌状态，不证明盖子打开；锁舌来源说明不适用于其他读数。电池评分不能用作健康诊断。集成按维护者规则将评分 0 显示为“不支持”，不能据此判断电池损坏或 SOH。

原生 MCP 将 JSON 结果作为文本内容返回。失败使用固定代码，如 `not_authorized`、`invalid_arguments`、`local_data_missing`、`retry_later`、`timeout`。查询失败不表示没有骑车；若返回 `retry_after_seconds`，应遵循等待时间，避免连续重试。

错误附带固定说明。`not_authorized` 表示访问未获授权，不能据此判断行程是否存在。车辆列表的`capabilities`描述本地就绪状态：`cached_status`表示曾成功收到状态，`local_history`表示账号档案已就绪。false不能推断车辆硬件不支持；实测值与新鲜度应读取状态工具。

同步健康返回配置的请求速率与最小间隔。账号预算用于控制历史请求间隔，不能据此推算自然小时内还剩多少次。应依据`next_request_at`与`retry_at`解释当前调度；配置为0仅取消配额节流，仍保留串行与上游退避。

从 2.2.6 起，`archive_counts` 覆盖选中车辆的全部本地行程，含导入记录和仅有摘要的行程，同时列出已保存详情、已确认简化轨迹和仍待判定轨迹质量的数量。`details` 对应当前扫描与保存计划。`ninebot.ask` 分别显示两组统计。参见[正确理解进度](history_zh.md#正确理解进度)。

2.1.24起，缓存状态可附带小型`quality.groups.<group>.failure_context`，仅包含当前已审阅的错误类别、本地请求／规范化／归档阶段、端点模板、代理HTTP／受控码、尝试时间和可重试性，不含原始响应、日志正文或身份。代理指本地backend的响应，不能据此认定云端地区、硬件故障或云端根因；恢复成功后清除。此投影与状态值使用相同的车辆同意和查询鉴权。

## 版本化帮助

版本化帮助和任务清单从 **2.1.1** 开始提供。

可以询问统计未知、请求额度、覆盖率、缺失详情、过期数值、单位、认证、保留规则或Assistant权限。`ninebot__search_help`搜索随包提供的双语主题，不访问网站、不索引私有档案。问题最多240字符；结果包含固定来源提交、来源及内容摘要、语言、适用版本和语料版本。帮助解释文档契约，当前车辆事实仍须通过相应数据工具查询。

语料 1.2.15 为 2.2.9 预览版提供 21 个适用的双语主题和 10 项辅助清单。询问如何回放历史轨迹，可以得到仪表盘指南的引用。通用帮助只核对授权，不读取车辆测量值或坐标。搜索 `get_recorded_trips`、`get_trip_detail` 或 `get_sync_health`（可带 `ninebot__` 前缀），可获取相应指南及其固定引文。`control_diagnostics` 适用于 2.1.26 起的版本，引用固定的 2.1.26 排障指南，解释 `control_routing`、`confirmation_deadline_reached`、`upstream_code` 和 `backend_error`。解读代理 502 时应先明确具体操作。命令响应、本地确认窗口和所选路径分别提供该次操作的不同证据。

数据缺失、控制回执和电池循环支持主题适用于 2.1.24 起的版本，引用固定的 2.1.23 指南。`sample_units` 解释未验证采样，`measurement_units` 解释最高速度、总平均速度和电池评分的含义。登录帮助涵盖 2.0.0 和 2.0.1 新增的支持记录。MCP 配置主题解释主地址和独立地址设置，并识别准确的配置键。检索优先匹配主题关键词，按各主题自身的版本范围和来源返回结果。每条命中返回固定 `citation` 和实际语料版本。原生工具回执把引文放在摘录前，客户端可以直接展示。原生 API 提示模型先给出完整引文，再简述回执支持的事实和核查步骤。采用自由生成答复的客户端仍负责其生成和展示。

从 **2.1.13** 起，请求额度检索会排除任务申请主题中的泛用词。准确的 `preview_detail_sync` 和 `request_detail_sync_approval` 名称可检索适用的任务清单；获准任务仍共享账号请求额度。

通用帮助不需要先选择车辆或日期。例如“等待请求额度是什么意思”可以直接检索帮助；“这辆车现在为什么等待”还需要读取所选车辆的同步健康结果。

遇到“App有数据、HA没有”，先明确字段与业务周期：当前值查缓存状态，某个统计未知查`explain_statistics`，历史缺口查同步健康与本地记录；字段含义和取证步骤查帮助。进度100%可能针对已确认的空分母；本地可发送、指令已接受与目标状态已观察分别表达。只读Assistant提供解释与指导，不发送控制，也不采集新的云端数据。

每次最多三条、4 KiB。不匹配时说明没有结果或没有适用版本的知识，不套用其他版本的规则；其他语言使用英文。语料损坏只影响帮助，六个车辆工具仍可用。引用始终指向固定提交，不随主分支文档变化。

## 任务流程

从 **2.1.6** 起，`search_help`的`include_procedures`默认`false`。默认返回主题、引用和`procedure_id`等元数据，`procedures`为空。指导具体任务时显式传入布尔值`true`，才返回适用版本、去重后的辅助清单，两种模式共用4 KiB上限。一般概念不要求选车；具体车辆的当前同步或缺口才需要车辆输入。

显式请求的清单说明触发条件、需追问的信息、允许工具、调用预算、停止条件和结果核验。范围包括选车、当前状态、周期统计、本地行程、统计未知、同步缺口、认证排障及指标语义。例如解释统计未知时，先读取指定周期的指标质量，再按需读取同步健康和对应帮助，不补零、不启动同步。

宿主在既有工具循环中使用辅助清单，每次调用仍接受程序鉴权。缺少输入须追问，权限拒绝须停止，无法判断时提供已观察证据和明确下一步。需要补齐历史详情时，按下节流程申请和人工审批。

## 可审核的历史任务（Beta）

开启助手后，在逐车设置中选择并保存**历史任务**权限。默认**关闭**。**仅预览**可查看本地缺口及本人已有任务。**允许申请**还可保存本地待审申请。管理员侧边栏的 **Ninebot Assistant** 面板供人审核或取消已有工作。

在宿主中选择 **Ninebot**。主地址 `/api/mcp` 启用只读时，原生服务器会过滤申请工具。发现列表可能为一辆车显示申请工具，而另一辆车只允许预览或查询。每次调用都按所请求的车辆验权。

| 任务工具 | 所需任务权限 | 返回内容 |
|---|---|---|
| `ninebot__task_vehicles` | 仅预览或允许申请 | 已开放历史任务的车辆。 |
| `ninebot__preview_detail_sync` | 仅预览或允许申请 | 最多 31 个业务日的本地缺口与请求额度。 |
| `ninebot__get_tasks` | 仅预览或允许申请 | 原申请人在该车上的已保存任务。 |
| `ninebot__get_task` | 仅预览或允许申请 | 一项本地任务的最近记录和结果。 |
| `ninebot__request_detail_sync_approval` | 允许申请且审核可用 | 保存待审申请，或返回匹配的已有申请。 |

预览日期范围不会提交申请。只有返回 `task_recorded: true` 和任务 ID，才表示申请已保存；之后由用户在审核面板批准，口头表示“接下来提交”不会创建任务。

选中详情条数与尝试额度分开计算。从 **2.1.12** 起，预览／申请使用 `requests.maximum_detail_attempts` 表达额度，与任务元数据同名。`attempts_include_retries: true` 和 `attempt_scope: entire_selection` 表示全部选中详情共用含重试的额度。例如选中 1 条详情、最多尝试 2 次，允许失败后重试，不会额外选中第 2 条详情。旧 `maximum_after_approval` 字段保留为等值别名。一次尝试指调度器发起一次详情请求，不代表 HTTP 传输次数，也不保证保存成功。

请使用与 AI 客户端相同的 Home Assistant 管理员用户登录。打开 **Ninebot Assistant**，选择车辆，核对日期、详情条数、总请求上限及有效期，再点击“批准并同步”。每个计划最多选中 20 条缺失详情，总请求额度为选中条数的两倍、最多 20 次；重试共享此额度和账号请求间隔，已保存的详情会复用。“取消任务”只停止本任务后续工作，其他同步继续运行。取消时由原申请人使用同一HA用户，在此面板点击“取消任务”；读取工具或聊天确认不能取消。未批准申请到期后不会执行，申请其他日期也不会撤销之前的申请。

页面展示最近已保存的进度、实际请求消耗、下次允许尝试时间和结果。审批窗口为 10 分钟，批准后执行期限为 24 小时；普通重启会恢复仍获准的工作，恢复官方 HA 备份后需要重新人工批准。审核页面只读取本地元数据，不刷新车辆状态，也不整月抓取云端数据。

原生通知会提供待审核或结果入口，每个账号合并为一条通用提醒，不包含账号、车辆、行程标识、位置或确认凭据。等待、重试计数及确认凭据轮换不会逐次产生通知。通知不是审批或完成证据，以审核面板中的持久任务状态为准；重启后仍可直接打开面板查看保存的任务。

两项任务清单各允许最多 4 次工具调用。申请流程先明确用户意图、车辆、日期和申请权限，再提交本地待审请求。核对结果可使用仅预览或允许申请权限，读取匹配任务，区分未知、零值、等待、部分完成与核验完成，并遵守重试时间。批准及取消均在人工审核面板执行。

读取期间若撤销相应数据或任务权限，该次读取会结束。重新授予权限后，可重开面板或发起新查询。明确撤销任务所需权限会使原授权下受保护的申请失效。

## 隐私与限额

统计排查先占用一次准入，每个子查询另占一次，完整三步共四次；活动读取槽位不嵌套，全部步骤共用10秒期限。幂等本地动作遇到已确认的Ninebot暂忙错误时至多重试一次，仍在原准入与期限内；分页游标、权限错误及未知错误不重放。成功结果的`query.local_action_attempts`记录底层本地动作次数，与模型工具调用数及云端额度区分。

启用选项后，所选宿主可以接收授权车辆的显示名称、标量数值、时间、行程标识及质量信息。请留意自行设置的车辆名称。工具不输出账号凭据、账号标识、序列号、精确坐标、原始响应、日志、完整轨迹和采样数组。外部模型宿主可能按其自身政策保存对话与工具结果。关闭选项会撤销后续调用权限，无法移除已经发送给宿主的信息；车辆选择会保留，便于下次开启。

专属 API 每位已认证用户**滚动一分钟最多20次调用**，整个 API **最多两次并发**，单次调用限时 **10秒**；结果上限 **16 KiB**，列表每条行程上限 **2 KiB**。最多返回20辆授权车辆，存在更多车辆时会明确提示，应收窄账号中的 AI 车辆选择。这些本地限额独立于云端历史请求额度，宿主将取消传递给工具后，该调用会释放准入名额。模型生成的整段截止与重试由所选宿主控制，十秒限时适用于每次 Ninebot 工具调用。

**Ninebot** 集合不包含车辆控制及档案导入、删除。选择其他 Home Assistant API 会授予那些集合的能力。若要在所有宿主中禁止某辆车的任务申请，请将该车设为**关闭**或**仅预览**。云端执行须在审核面板人工批准。

## 常见问题

| 情况 | 检查方式 |
|---|---|
| API 列表没有 Ninebot | 确认已安装支持 Assistant 的版本、HA 具备所需的原生 API，且至少有一个已加载的账号启用了 Assistant 并选择车辆。 |
| `API ninebot_tasks not found` | 在宿主已保存的 AI 工具中取消 **Ninebot tasks**，保留 **Ninebot** 和其他选择，再新建会话。 |
| 没有车辆或 `not_authorized` | 检查当前有效管理员身份、账号同意及车辆归属；远程控制授权不会自动授予AI访问权。 |
| 找不到任务申请工具 | 检查该车是否允许申请、审核服务是否可用、宿主是否允许写入。如有提示，先完成一次性权限确认。 |
| 找不到行程详情 | 先从已保存列表取得准确 `ride_id` 和 `query_month`，缺失详情通过正常历史同步采集。 |
| 统计部分覆盖或未知 | 查看结果来源、覆盖和同步健康；只读工具不会自动修复档案。 |
| 触发限流或超时 | 遵循重试间隔并减少并发调用，集成不会为AI新增轮询循环。 |
| 需要反馈问题 | 按[日常使用指南](guide_zh.md#常见问题)使用集成原生日志和经审阅的诊断信息，发布前移除私人对话内容。 |
