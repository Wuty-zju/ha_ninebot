# Ninebot Assistant — 2.1 预览

[English](assistant.md) · [文档](README.md) · [历史行程与地图](history_zh.md)

Ninebot Assistant 通过 Home Assistant 原生 LLM API 和 MCP Server，向兼容的 AI 宿主提供用户选定车辆的本地信息。预览提供本地车辆查询、有界统计排查和版本化公开帮助，现有实体、控制及历史同步继续独立运行。

## 开启方式

1. 从 Marketplace/HACS 安装 **2.1.x 预发布版**，或安装对应发行包。推荐正式版仍为 [v2.0.0](https://github.com/Wuty-zju/ha_ninebot/releases/tag/v2.0.0)。
2. 原生 Assistant API 使用 **Home Assistant 2026.11+**。普通车辆功能仍维持 **2026.1.0** 最低版本；缺少所需原生 API 时不显示 Assistant 选项。
3. 打开需要授权账号的 **设置 → 设备与服务 → Ninebot → 配置**，启用 **Ninebot Assistant（Beta）** 并选择车辆。默认关闭且不选车辆，此范围独立于远程控制白名单。
4. 在原生 **MCP Server** 集成中，关闭访问全部 LLM API，仅选择 **Ninebot**，保留管理员要求并开启只读模式。按 Home Assistant 支持的认证方式，将 MCP 客户端连接到 `/api/mcp`。
5. 使用有效的管理员身份。每次工具调用都会重新检查用户、账号开关和车辆授权；没有用户身份的调用会被拒绝。

使用原生 Conversation/Assist 宿主时，若宿主支持自定义 LLM API 并保留已认证用户 Context，可选择 **Ninebot** API。具体选项和工具支持取决于宿主。Ninebot 不配置模型、模型密钥或额外监听服务。通用 Action 工具与暴露实体属于独立能力；注册 Ninebot Action 本身不会自动启用这些专属工具。

支持提示模板的 MCP 客户端可通过 `prompts/list` 和 `prompts/get` 获取 **Ninebot** 模板，并在客户端的提示入口应用它。仅发现工具不代表客户端已应用这份说明。无论是否支持模板，工具调用始终执行相同的权限校验。

## 选择宿主和模型

Ninebot Assistant 使用 Home Assistant 原生 LLM API 和 MCP 工具。在选用的 HA 对话代理或 MCP 客户端中配置模型；宿主需要支持工具调用、Ninebot 集合并保留已认证用户上下文。集成不要求指定模型厂商、本机推理引擎或模型权重。

宿主负责对话与模型访问，Ninebot 提供获准的本地查询、版本化帮助、任务清单及独立的人类审核任务 API。模型选择和回答展示由宿主负责，所有模型使用相同的工具参数及权限检查。

固定模型和参考宿主仅用于开发评测，说明见[开发指南](development.md#small-model-baseline)，与上述用户安装和模型配置分开维护。

## 通过已有AI任务查询

从 **2.1.15** 起，可在 **开发者工具 → 动作 → Ninebot：询问 Ninebot Assistant** 发起有界本地查询。先在账号选项中启用Assistant并选择车辆，再选择支持原生工具调用和逐次LLM API的已有 **AI任务** 实体。填写问题；允许多辆车时明确选择车辆。调用需要当前有效管理员身份，模型仍在所选供应商集成中配置。

```yaml
action: ninebot.ask
data:
  ai_task_entity_id: ai_task.your_model
  device_id: your_ninebot_device_id
  question: 这辆车昨天骑了几趟？
response_variable: ninebot_answer
```

响应的`answer_mode`为`verified_tool_results`，`results`保留实际工具名、参数、数据、质量和来源。`outcome: evidence`表示获得了数据或帮助结果；解读总量前仍需核对实际周期与覆盖情况，不代表模型理解了问题的全部内容。只有车辆列表或没有有效数据结果时为`needs_input`，请补充车辆、日期或更明确的问题；提前停止但已有证据时为`partial`。失败和拒绝访问不会变成零行程。

模型供应商在成功读取数据或帮助之后失败时，响应会保留重新核验过的工具结果，标记为`outcome: partial`和`stop_reason: model_task_failed`。只有失败读取或车辆列表时仍返回失败；权限撤销后不返回这些结果。

模型从八个本地工具中选择调用，自由生成的最终文字不作为数值或来源；响应保留实际工具结果。一般帮助不要求车辆选择。单次上限180秒、四次工具调用、32 KiB响应，集成同一时间接受一个此类查询。不会刷新云端、申请历史任务或控制车辆。模型任务和业务读取沿用原调用身份，结果返回前重新校验同意、归属与权限。

需要Core支持`ai_task.async_generate_data(..., llm_api=...)`并已有兼容供应商；不支持时返回`unsupported_capability`，不会自动安装模型或另开端口。原生MCP／Conversation八工具仍可独立使用，此动作不加入专属LLM工具集合。

## 查询本地数据

例如：

- “Vehicle A 昨天骑了几趟？”
- “Vehicle A 上个月耗电多少？”
- “Vehicle A 在2026年11月5日骑了几趟？”
- “列出 Vehicle A 11月5日的行程，再查看选中行程的已保存详情。”
- “Vehicle A 当前状态是否新鲜？”
- “历史同步在等待什么？”

有多辆车时，先选定车辆再查询数值。宿主从 `ninebot__get_vehicles` 获取不透明的 `vehicle_ref`；账号、车辆序列号及表示 MCP 客户端来源的 `device_id` 均不能替代它。

| 工具 | 参数 | 返回内容 |
|---|---|---|
| `ninebot__search_help` | `query`；可选 `language`（`en` 或 `zh-Hans`）、`include_procedures`（默认 `false`） | 最多三条附引用的公开帮助；指导具体任务时显式请求任务清单。 |
| `ninebot__get_vehicles` | 无 | 已向 AI 授权的车辆引用、显示名称及本地数据能力。 |
| `ninebot__get_vehicle_status` | `vehicle_ref` | 缓存状态/BMS 数值及分组观测质量，不刷新、不返回坐标。 |
| `ninebot__get_statistics` | `vehicle_ref`、`period` | 本地 `today`、`yesterday`、`this_month`、`last_month` 或单个明确业务日期／月份的统计及逐指标覆盖情况。 |
| `ninebot__get_recorded_trips` | `vehicle_ref`、`start_date`、`end_date`；可选 `limit`、`cursor` | 一页按时间倒序排列的本地行程。日期格式 `YYYY-MM-DD`，含首尾最多31天；默认10条，最多20条。 |
| `ninebot__get_trip_detail` | `vehicle_ref`、`ride_id`、`query_month` | 对应车辆及月份中已验证行程的本地标量详情。使用列表返回的行程 ID 和 `YYYYMM` 月份。 |
| `ninebot__get_sync_health` | `vehicle_ref` | 本地覆盖、进度、额度和调度状态，不启动或恢复同步。 |
| `ninebot__explain_statistics` | `vehicle_ref`、`period`、`metric`；可选 `language` | 三个本地步骤：周期统计、同步健康、附引用的帮助与统计排查清单。 |

全部工具均读取本地信息。缺失详情需要通过正常的[历史功能](history_zh.md)采集；AI 只读调用不会触发云请求。列表游标可能被消费，应继续使用返回的下一页游标，不反复重放上一游标。一页记录数量不代表整个时间段的行程总数。

从 **2.1.10** 起，`get_statistics` 的 `period` 也接受一个 `YYYY-MM-DD` 日期，例如 `2026-11-05`。日期沿用 Asia/Shanghai，范围从2000年起，不接受未来日期；查询读取已有本地日投影。已验证的空日可返回0，未观测日期保持未知，原四个相对周期继续可用。

从 **2.1.17** 起，`period` 也接受 `YYYY-MM`，例如 `2026-10`。已结束月份取完整自然月，当前月份截至当前业务日；年份从2000年起，不接受未来月份。月统计使用已有服务端月汇总，与每日投影及行程分页小计分别表达。

排查具体数值时，可用 `ninebot__explain_statistics` 指定车辆、周期及一个指标：`ride_count`、`distance_km`、`duration_s`、`energy_wh` 或 `energy_intensity_wh_per_km`。固定流程返回实际统计、同步健康、适用版本的帮助引用与SK05清单。`data.steps`保留各工具结果及观测时间，`quality.partial`表示有步骤失败或未执行。指标原因描述目前的证据，不直接判定根因；此查询不修复数据、不启动云端任务。

从 **2.1.9** 起，行程分页保留每条记录的 `received_at`，并在 `quality.months` 返回最多三个月份的观测摘要，空页也保留这些信息。`query.as_of` 表示本次工具调用时间，`quality.page_as_of` 表示游标各页沿用的选取截止时点，均与档案的实际观测时间区分。固定截止时点不等于冻结整个数据库，也不能证明云端完整性；缺失的观测信息保持 `null`。

## 理解数据依据

结果包含业务日期范围、观测时间、单位、指标质量、来源证据及提示。业务日期沿用当前档案契约的 **Asia/Shanghai**，不随浏览器时区变化。

- 已确认没有行程的周期可以返回 **0**；缺失数值为 **null**，附带原因或质量信息。
- 部分覆盖仅代表目前已知记录，不能据此确认完整总量。
- 当前状态可能陈旧；已结束月份的历史事实不会仅因时间久而被判过期。
- 每日里程图与按行程结束日期归属的统计采用不同来源投影，结果会标明依据。
- 最高速度与距离除以时长得出的总平均速度分别表达；未知采样单位保持待验证。
- `acc_active` 表示电门状态，不证明车辆移动或正在骑行。`seat_locked` 只表示座桶锁舌状态，不证明盖子打开；锁舌来源说明不适用于其他读数。电池评分不能用作健康诊断。集成按维护者规则将评分 0 显示为“不支持”，不能据此判断电池损坏或 SOH。

原生 MCP 将 JSON 结果作为文本内容返回。失败使用固定代码，如 `not_authorized`、`invalid_arguments`、`local_data_missing`、`retry_later`、`timeout`。查询失败不表示没有骑车；若返回 `retry_after_seconds`，应遵循等待时间，避免连续重试。

错误附带固定说明。`not_authorized` 表示访问未获授权，不能据此判断行程是否存在。车辆列表的`capabilities`描述本地就绪状态：`cached_status`表示曾成功收到状态，`local_history`表示账号档案已就绪。false不能推断车辆硬件不支持；实测值与新鲜度应读取状态工具。

同步健康返回配置的请求速率与最小间隔。账号预算用于控制历史请求间隔，不能据此推算自然小时内还剩多少次。应依据`next_request_at`与`retry_at`解释当前调度；配置为0仅取消配额节流，仍保留串行与上游退避。

## 版本化帮助

版本化帮助和任务清单从 **2.1.1** 开始提供。

可以询问统计未知、请求额度、覆盖率、缺失详情、过期数值、单位、认证、保留规则或Assistant权限。`ninebot__search_help`搜索随包提供的双语主题，不访问网站、不索引私有档案。问题最多240字符；结果包含固定来源提交、来源及内容摘要、语言、适用版本和语料版本。帮助解释文档契约，当前车辆事实仍须通过相应数据工具查询。

当前语料1.2.6包含14个双语主题和10项辅助任务清单。`sample_units`单独解释逐点采样单位、第四列及`mph`等尚未验证的问题；`measurement_units`保留最高速度、总行程平均速度与电池评分语义。每条命中返回`citation`，包含固定来源链接和实际语料版本，可供客户端直接展示。登录排障知识注明2.0.1新增的支持记录与2.0.0的差别。检索优先匹配主题关键词，减少共用词带入的无关内容。来源契约版本仍为2.1.2；语料更新不代表未知字段已被验证。

从 **2.1.13** 起，请求额度检索会排除任务申请主题中的泛用词。准确的 `preview_detail_sync` 和 `request_detail_sync_approval` 名称可检索适用的任务清单；获准任务仍共享账号请求额度。

通用帮助不需要先选择车辆或日期。例如“等待请求额度是什么意思”可以直接检索帮助；“这辆车现在为什么等待”还需要读取所选车辆的同步健康结果。

每次最多三条、4 KiB。不匹配时说明没有结果或没有适用版本的知识，不套用其他版本的规则；其他语言使用英文。语料损坏只影响帮助，六个车辆工具仍可用。引用始终指向固定提交，不随主分支文档变化。

## 任务流程

从 **2.1.6** 起，`search_help`的`include_procedures`默认`false`。默认返回主题、引用和`procedure_id`等元数据，`procedures`为空。指导具体任务时显式传入布尔值`true`，才返回适用版本、去重后的辅助清单，两种模式共用4 KiB上限。一般概念不要求选车；具体车辆的当前同步或缺口才需要车辆输入。

显式请求的清单说明触发条件、需追问的信息、允许工具、调用预算、停止条件和结果核验。范围包括选车、当前状态、周期统计、本地行程、统计未知、同步缺口、认证排障及指标语义。例如解释统计未知时，先读取指定周期的指标质量，再按需读取同步健康和对应帮助，不补零、不启动同步。

宿主在既有工具循环中使用清单，无需另装Skill或执行框架。清单是辅助资料，不能授予权限；每次调用仍接受程序鉴权。缺少输入须追问，权限拒绝须停止，无法判断时提供已观察证据和明确下一步。申请同步和审批仍不属于这个只读预览。

## 可审核的历史任务（Beta）

**2.1.2** 起提供独立的“允许审核历史同步任务（Beta）”选项。先启用 Assistant 并选择车辆，再启用此选项并保存，管理员侧边栏将出现 **Ninebot Assistant**。任务功能默认关闭。

需要 AI 客户端申请同步时，选择独立的 **Ninebot tasks** 原生 API。申请会写入本地待审计划，因此服务器启用只读选项时，全局 `/api/mcp` 路径会隐藏申请工具；普通本地查询与帮助继续使用 **Ninebot** 集合。任务工具可列出获准车辆、预览最多 31 个业务日的缺失详情、申请人工审核并查询进度，不能自行批准。

支持多选 API 的宿主可同时选择 **Ninebot** 和 **Ninebot tasks**，在申请任务时使用版本化帮助与任务清单。从 **2.1.11** 起，两种选择顺序均保留任务标识的类型与格式约束。

预览日期范围不会提交申请。只有返回 `task_recorded: true` 和任务 ID，才表示申请已保存；之后由用户在审核面板批准，口头表示“接下来提交”不会创建任务。

选中详情条数与尝试额度分开计算。从 **2.1.12** 起，预览／申请使用 `requests.maximum_detail_attempts` 表达额度，与任务元数据同名。`attempts_include_retries: true` 和 `attempt_scope: entire_selection` 表示全部选中详情共用含重试的额度。例如选中 1 条详情、最多尝试 2 次，允许失败后重试，不会额外选中第 2 条详情。旧 `maximum_after_approval` 字段保留为等值别名。一次尝试指调度器发起一次详情请求，不代表 HTTP 传输次数，也不保证保存成功。

请使用与 AI 客户端相同的 Home Assistant 管理员用户登录。打开 **Ninebot Assistant**，选择车辆，核对日期、详情条数、总请求上限及有效期，再点击“批准并同步”。每个计划最多选中 20 条缺失详情，总请求额度为选中条数的两倍、最多 20 次；重试共享此额度和账号请求间隔，已保存的详情会复用。“取消任务”只停止本任务后续工作，其他同步继续运行。

页面展示最近已保存的进度、实际请求消耗、下次允许尝试时间和结果。审批窗口为 10 分钟，批准后执行期限为 24 小时；普通重启会恢复仍获准的工作，恢复官方 HA 备份后需要重新人工批准。审核页面只读取本地元数据，不刷新车辆状态，也不整月抓取云端数据。

原生通知会提供待审核或结果入口，每个账号合并为一条通用提醒，不包含账号、车辆、行程标识、位置或确认凭据。等待、重试计数及确认凭据轮换不会逐次产生通知。通知不是审批或完成证据，以审核面板中的持久任务状态为准；重启后仍可直接打开面板查看保存的任务。

从 2.1.2 起，版本帮助增加“申请有界详情同步”和“核对任务结果”两项流程。它们要求已暴露独立任务 API，最多使用 4 次工具调用；普通只读流程不能因此获得申请或审批能力。申请流程先明确用户意图、车辆与日期，再预览并提交本地待审请求；结果流程只读匹配任务，区分未知、零值、等待、部分完成与核验完成，不循环查询。

## 隐私与限额

统计排查先占用一次准入，每个子查询另占一次，完整三步共四次；活动读取槽位不嵌套，全部步骤共用10秒期限。幂等本地动作遇到已确认的Ninebot暂忙错误时至多重试一次，仍在原准入与期限内；分页游标、权限错误及未知错误不重放。成功结果的`query.local_action_attempts`记录底层本地动作次数，与模型工具调用数及云端额度区分。

启用选项后，所选宿主可以接收授权车辆的显示名称、标量数值、时间、行程标识及质量信息。请留意自行设置的车辆名称。工具不输出账号凭据、账号标识、序列号、精确坐标、原始响应、日志、完整轨迹和采样数组。外部模型宿主可能按其自身政策保存对话与工具结果。关闭选项会撤销后续调用权限，无法移除已经发送给宿主的信息；车辆选择会保留，便于下次开启。

专属 API 每位已认证用户**滚动一分钟最多20次调用**，整个 API **最多两次并发**，单次调用限时 **10秒**；结果上限 **16 KiB**，列表每条行程上限 **2 KiB**。最多返回20辆授权车辆，存在更多车辆时会明确提示，应收窄账号中的 AI 车辆选择。这些本地限额独立于云端历史请求额度，宿主将取消传递给工具后，该调用会释放准入名额。模型生成的整段截止与重试由所选宿主控制，十秒限时适用于每次 Ninebot 工具调用。

同时选择更广泛的管理员 API，会向宿主提供超出本专属只读契约的能力。只需要这些查询时，请选择专属集合及原生只读设置。只读集合不提供车辆控制、档案导入/删除或同步申请。独立任务集合可以申请审核，云端工作仍需在面板中由用户批准。

指定 `/api/mcp/<api_id>` 地址会直接选择已注册的集合，不继承全局 API 选择或只读设置。`/api/mcp/ninebot` 集合始终只有只读工具；任务集合仍要求账号任务授权，云端执行仍须另行人工批准。

## 常见问题

| 情况 | 检查方式 |
|---|---|
| API 列表没有 Ninebot | 确认正在运行2.1预览、Core具备原生API，且至少一个已加载账号开启Assistant并选择车辆。 |
| 没有车辆或 `not_authorized` | 检查当前有效管理员身份、账号同意及车辆归属；远程控制授权不会自动授予AI访问权。 |
| 找不到行程详情 | 先从已保存列表取得准确 `ride_id` 和 `query_month`，缺失详情通过正常历史同步采集。 |
| 统计部分覆盖或未知 | 查看结果来源、覆盖和同步健康；只读工具不会自动修复档案。 |
| 触发限流或超时 | 遵循重试间隔并减少并发调用，集成不会为AI新增轮询循环。 |
| 需要反馈问题 | 按[日常使用指南](guide_zh.md#常见问题)使用集成原生日志和经审阅的诊断信息，发布前移除私人对话内容。 |
