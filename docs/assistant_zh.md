# Ninebot Assistant — 2.1 预览

[English](assistant.md) · [文档](README.md) · [历史行程与地图](history_zh.md)

Ninebot Assistant 通过 Home Assistant 原生 LLM API 和 MCP Server，向兼容的 AI 宿主提供用户选定车辆的本地信息。首个预览提供六个只读工具，现有实体、控制及历史同步继续独立运行。

## 开启方式

1. 从 Marketplace/HACS 安装 **2.1.x 预发布版**，或安装对应发行包。推荐正式版仍为 [v2.0.0](https://github.com/Wuty-zju/ha_ninebot/releases/tag/v2.0.0)。
2. 原生 Assistant API 使用 **Home Assistant 2026.11+**。普通车辆功能仍维持 **2026.1.0** 最低版本；缺少所需原生 API 时不显示 Assistant 选项。
3. 打开需要授权账号的 **设置 → 设备与服务 → Ninebot → 配置**，启用 **Ninebot Assistant（Beta）** 并选择车辆。默认关闭且不选车辆，此范围独立于远程控制白名单。
4. 在原生 **MCP Server** 集成中，关闭访问全部 LLM API，仅选择 **Ninebot**，保留管理员要求并开启只读模式。按 Home Assistant 支持的认证方式连接 MCP 客户端。
5. 使用有效的管理员身份。每次工具调用都会重新检查用户、账号开关和车辆授权；没有用户身份的调用会被拒绝。

使用原生 Conversation/Assist 宿主时，若宿主支持自定义 LLM API 并保留已认证用户 Context，可选择 **Ninebot** API。具体选项和工具支持取决于宿主。Ninebot 不配置模型、模型密钥或额外监听服务。通用 Action 工具与暴露实体属于独立能力；注册 Ninebot Action 本身不会自动启用这些专属工具。

原生 MCP 请求处理及工具链使用合成授权和本地记录进行检查。模型表现和认证配置取决于所选宿主；本预览尚无实际测量的模型质量评分。

## 查询本地数据

例如：

- “Vehicle A 昨天骑了几趟？”
- “Vehicle A 上个月耗电多少？”
- “列出 Vehicle A 11月5日的行程，再查看选中行程的已保存详情。”
- “Vehicle A 当前状态是否新鲜？”
- “历史同步在等待什么？”

有多辆车时，先选定车辆再查询数值。宿主从 `ninebot__get_vehicles` 获取不透明的 `vehicle_ref`；账号、车辆序列号及表示 MCP 客户端来源的 `device_id` 均不能替代它。

| 工具 | 参数 | 返回内容 |
|---|---|---|
| `ninebot__get_vehicles` | 无 | 已向 AI 授权的车辆引用、显示名称及本地数据能力。 |
| `ninebot__get_vehicle_status` | `vehicle_ref` | 缓存状态/BMS 数值及分组观测质量，不刷新、不返回坐标。 |
| `ninebot__get_statistics` | `vehicle_ref`、`period` | 本地 `today`、`yesterday`、`this_month`、`last_month` 统计及逐指标覆盖情况。 |
| `ninebot__get_recorded_trips` | `vehicle_ref`、`start_date`、`end_date`；可选 `limit`、`cursor` | 一页按时间倒序排列的本地行程。日期格式 `YYYY-MM-DD`，含首尾最多31天；默认10条，最多20条。 |
| `ninebot__get_trip_detail` | `vehicle_ref`、`ride_id`、`query_month` | 对应车辆及月份中已验证行程的本地标量详情。使用列表返回的行程 ID 和 `YYYYMM` 月份。 |
| `ninebot__get_sync_health` | `vehicle_ref` | 本地覆盖、进度、额度和调度状态，不启动或恢复同步。 |

六个工具全部读取本地信息。缺失详情需要通过正常的[历史功能](history_zh.md)采集；AI 只读调用不会触发云请求。列表游标可能被消费，应继续使用返回的下一页游标，不反复重放上一游标。一页记录数量不代表整个时间段的行程总数。

## 理解数据依据

结果包含业务日期范围、观测时间、单位、指标质量、来源证据及提示。业务日期沿用当前档案契约的 **Asia/Shanghai**，不随浏览器时区变化。

- 已确认没有行程的周期可以返回 **0**；缺失数值为 **null**，附带原因或质量信息。
- 部分覆盖仅代表目前已知记录，不能据此确认完整总量。
- 当前状态可能陈旧；已结束月份的历史事实不会仅因时间久而被判过期。
- 每日里程图与按行程结束日期归属的统计采用不同来源投影，结果会标明依据。
- 最高速度与距离除以时长得出的总平均速度分别表达；未知采样单位保持待验证。
- ACC 不证明车辆移动；座桶锁舌状态不证明盖子打开；电池评分不能用作健康诊断。

原生 MCP 将 JSON 结果作为文本内容返回。失败使用固定代码，如 `not_authorized`、`invalid_arguments`、`local_data_missing`、`retry_later`、`timeout`。查询失败不表示没有骑车；若返回 `retry_after_seconds`，应遵循等待时间，避免连续重试。

## 隐私与限额

启用选项后，所选宿主可以接收授权车辆的显示名称、标量数值、时间、行程标识及质量信息。请留意自行设置的车辆名称。工具不输出账号凭据、账号标识、序列号、精确坐标、原始响应、日志、完整轨迹和采样数组。外部模型宿主可能按其自身政策保存对话与工具结果。关闭选项会撤销后续调用权限，无法移除已经发送给宿主的信息；车辆选择会保留，便于下次开启。

专属 API 每位已认证用户**滚动一分钟最多20次调用**，整个 API **最多两次并发**，单次调用限时 **10秒**；结果上限 **16 KiB**，列表每条行程上限 **2 KiB**。最多返回20辆授权车辆，存在更多车辆时会明确提示，应收窄账号中的 AI 车辆选择。这些本地限额独立于云端历史请求额度，取消调用会释放该调用的准入名额。

同时选择更广泛的管理员 API，会向宿主提供超出本专属只读契约的能力。只需要这些查询时，请选择专属集合及原生只读设置。首版不提供车辆控制、档案导入/删除或由 AI 启动同步的工具。

## 常见问题

| 情况 | 检查方式 |
|---|---|
| API 列表没有 Ninebot | 确认正在运行2.1预览、Core具备原生API，且至少一个已加载账号开启Assistant并选择车辆。 |
| 没有车辆或 `not_authorized` | 检查当前有效管理员身份、账号同意及车辆归属；远程控制授权不会自动授予AI访问权。 |
| 找不到行程详情 | 先从已保存列表取得准确 `ride_id` 和 `query_month`，缺失详情通过正常历史同步采集。 |
| 统计部分覆盖或未知 | 查看结果来源、覆盖和同步健康；只读工具不会自动修复档案。 |
| 触发限流或超时 | 遵循重试间隔并减少并发调用，集成不会为AI新增轮询循环。 |
| 需要反馈问题 | 按[日常使用指南](guide_zh.md#常见问题)使用集成原生日志和经审阅的诊断信息，发布前移除私人对话内容。 |
