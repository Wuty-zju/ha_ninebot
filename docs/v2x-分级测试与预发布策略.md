# v2.x 分级测试与预发布策略

2026-10-04，b18；执行用户关于加快开发、避免每个prerelease完整测试的要求。
此策略覆盖旧报告中“每个版本重跑全部测试”的发布流程，不放宽生产只读、
隐私、实体身份、明确未知语义与精确依赖pin等约束。

## 小版本

小范围缺陷修复、文档、翻译或界面调整：只运行受影响行为的针对性离线回归，
代码改动按需Ruff/format/mypy；不重复全量测试或多版本矩阵。每个完成的
小版本仍合入main、推送版本更新并发布下一个prerelease，记录实际测试范围。
例：b18非法profile不能提交native cache，20项native车辆测试覆盖成功/失败/
取消/输出边界及新回滚；不追加云端或车辆请求。

日常PR/main的Checks只运行Ruff/format，既有Hassfest/HACS继续执行。绿色
Checks表示这些项目通过，不能表述为“全部pytest/三版本兼容通过”。

## 重大阶段

新增重要功能、改raw schema/身份迁移/会话生命周期/兼容分支时，阶段完成后
在最终候选提交手动运行Checks（Run workflow，指定开发分支或main）。这会
执行完整pytest、覆盖率和当前固定的最低/稳定/beta HA三版本矩阵。
Hassfest/HACS仍独立运行；如果流程只修改文档，不为了版本号重跑完整套件。
同一提交检查通过后不重复；后续只有相关实质改动、失败或未解决风险才加测。

真实只读smoke仅用于fixture无法回答的新接口/schema/发布候选疑点，一次
采全后脱敏离线分析。控制测试按已有明确授权及必要性执行，不用作日常回归。
运行中HA仍仅为只读参考源，不改配置/registry/数据库/安装或重启。

## 发布记录

每次记录：版本、起始提交、针对性/完整测试实际运行范围和结果；核实合并后
main精确SHA、常规检查、release为prerelease且tag指向该提交。历史完整测试
作为基线保存，不能冒充当前小版本新跑的结果。每阶段保持独立可审阅提交。
