# 升级、实体身份与回滚

[English](migration.md) · [文档入口](README.md)

## rc1 升级 rc2

原有自定义轮询周期保持原目标，直到在选项中主动选档；原60秒／默认配置使用均衡档。仅修改刷新速度会直接应用到当前运行实例。档案格式、实体身份、历史开关和控制确认窗口保持不变。旧版本不识别新档位设置；如回退代码，请在旧版重新设置其轮询周期。

取消导入会等待正在执行的文件操作和档案读取结束，再清理暂存目录。旧库整合被中断时保留原始来源，供下次继续处理。

## 升级前

备份**完整且版本对应的 HA 配置/存储**：registry、ConfigEntry、账号会话、身份/额定参数存储、私有历史库和恢复副本。它们包含凭据与位置数据。仅回退代码或恢复 SQLite 不会撤销身份/存储迁移。

安装完整的所选版本，按 HA/HACS 提示重启；更新卡片后刷新浏览器。既有 `custom:ninebot-trip-card` 配置与资源路径保持支持。不要把删掉重建集成当作正常升级步骤。

## 从 1.x 到 2.0

2.0 替换旧后端并重整认证、快照、调度与历史存储，可能需要重新认证。既有有意义的实体身份和已审核 alias 通过迁移延续，不盲目重建；厂商 API 与平台依赖限制仍存在。

初版记录见[固定历史迁移矩阵](https://github.com/Wuty-zju/ha_ninebot/blob/9ba20bcadea1ea0500d9c080e60a48adc35e2387/docs/2.0-实体迁移矩阵.md)，它不是另一套现行手册。

## ID 与名称

```text
<platform>.<account_slug>_<vehicle_model_slug>_<serial_slug>_<stable_key>
```

优先使用 ASCII 车型词；中文/有损/过长输入使用确定性 hash 后缀，冲突不随意加 `_2`。命名种子固定，昵称/账号标签/车型变化不会持续重命名；翻译展示名称与身份分开。

b36 曾保守迁移生成 ID；**b44 随后对已加载车辆执行一次规范迁移，包含此前自定义 ID**。之后用户改名不在每次重载时覆盖。阅读旧发布说明需区分阶段。

有意义的 unique_id 与用户元数据受保护，依靠专属归属、冲突检查、持久身份日志及 HA registry API 迁移。占用目标、外来归属、并发改名产生 Repair，不覆盖/删除；既有身份库损坏时可能阻止设置，以防重复实体。

## 查看迁移映射

开发者工具 → 动作，或支持响应的脚本：

```yaml
action: ninebot.get_entity_migration
data:
  device_id: REPLACE_WITH_VEHICLE_DEVICE_ID
response_variable: mapping
```

返回前缀、旧/新 ID、状态和原因；纯本地读取，包含私有身份信息，不要公开。根据映射更新 YAML、模板、自动化与外部卡片；不保证自动改写所有引用。

## 车辆锁与座桶锁

b38 将已审核的旧上锁/解锁 binary sensor 和座桶 sensor 转为原生 Lock，安全归属明确时保留 unique_id 字符串及适用的名称、图标、区域、标签、别名、禁用/隐藏选择。跨平台需要新的 registry 行。

旧 Recorder 数据仍在旧实体 ID，新 Lock 独立开始历史；自动化条件须相应从 on/off 改为 locked/unlocked。同平台改名由 HA 处理历史/统计元数据，但不会合并无关的已存在历史。

## 已退役实体

低信插件电量累计估算和已审核重复实体不恢复。额定 V/Ah/kWh 是规格，不是实测容量/SOH。三种云续航为不同字段，缺报不相互替代。

旧手动历史任务实体与现有自动历史进度实体是不同阶段；旧版“无进度实体”不代表应删除当前进度 sensor。不删除 Recorder 行做展示清理。

## 存储升级与回滚

升级前验证旧库、检查空间，创建独占一致的 `rides.schema<old>-<digest>.sqlite3`，再事务修改 schema。原始证据与断点保留在账号档案内；整合校验成功后清理非活动旧文件和结构安全副本。回退请使用外部／完整 HA 备份。

旧版本可能无法读取新 schema/身份日志。集成停止后，在受控恢复环境恢复匹配的完整升级前备份；保留唯一原件，旧副本没有之后采集的新数据。不要覆盖运行中的库、手改 schema 标记或删库强制设置。

通过受支持的[校验与恢复](history_zh.md#校验与恢复)流程使用 `.recovery-<job_id>.sqlite3` 等任务恢复副本。版本回退使用匹配的完整 HA 备份，保留未解决的 Repair 供诊断。


## 历史控制与调试实体

同步历史行程按钮现同时负责恢复已暂停任务；旧“恢复历史同步”按钮退役，引用它的自动化请改用现有同步按钮，或继续调用兼容的 `ninebot.sync_history`、`operation: resume`。暂停按钮保留。已有行程、其他实体身份和用户命名不变。

调试关闭时，相关诊断实体由集成禁用并隐藏，开启后恢复原身份；用户自己禁用/隐藏的选择继续保留。默认预算改为60，上限120；已有有效预算不会被覆盖。

## b101行程事件与时长显示

两个最近行程起止时间传感器合并至既有车辆行程事件。仪表盘/模板改读`latest_start_time`和`latest_end_time`属性；不删除归档或旧Recorder记录。车辆状态事件改发具体类型，原来过滤`state_changed`的自动化需调整。事件ID及其它行程传感器身份保留。时长显示一次迁移为小时/四位小数。既有日历/历史选项保持用户选择，仅新账号默认关闭这些Beta功能。

## 按账号归属的归档目录

历史归档使用稳定的已认证账号目录。schema 7 将同账号条目库、旧 imports／retired 副本、恢复点和支持的结构快照合并到唯一主库。每个来源先在隔离副本升级、校验和提交，成功后才删除对应受管文件；独立业务原始响应保存在主库内。外账号、未知名称、符号链接、变化中／使用中的文件和失败来源不删除；单个来源失败不影响健康主库，未完成的清理通过 Repair 提示。

**升级前备份 Home Assistant。** 成功合并会清理旧本地库，降级需要匹配的外部／完整 HA 备份。同账号重新添加会接回主库，实体身份保持。不覆盖运行中的库，不手工修改 schema 标记。
