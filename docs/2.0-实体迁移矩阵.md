## 身份、可用性和统计契约

同平台且同口径的实体通过显式 alias 保留已有 unique_id、entity_id、用户命名与禁用设置。
新实体使用 `<SN>_<key>`，SN保留大小写；不依据昵称或简单转小写合并车辆。
DeviceInfo 保持 `(ninebot, SN)`。存在A/B同功能身份冲突时，不删除注册项；等价传感器
继续提供值并产生脱敏Repair。旧注册表未匹配到可靠来源时保留，不自动清理。

表中的“关闭”是新实体的默认状态，不覆盖旧用户自行开启/禁用的选择。
“旧兼容”仅从已存在的注册项生成，native_value=None，并提供deprecated原因。
旧历史与统计不改写，模型变化和跨平台替代使用新身份。不能把unknown写成0。

status新鲜度为max(3×轮询周期,180秒)，BMS/travel为1800秒，profile为10800秒；
账号认证失败、车辆不再存在、卸载及数据组超期会令对应实体不可用。成功响应缺失字段
呈unknown。查询接收时间不是车辆上报时间。月初旧月份travel立即不满足可用性条件。

本文“测量”指HA SensorStateClass.MEASUREMENT；“累计”指TOTAL_INCREASING；
“无”指不声明state_class。云端返回续航属于云端算法估计，不是实车续航保证。

估算新ID为`<SN>_estimated_<key>_v2_g<generation>`。初次/重启/重新启用、长失联和
异常SOC只建立基线，当前样本量保持未知；有效零变化可以为0。模型参数或可辨认的
电池来源变化切generation并清空该新模型累计，不把跳变记能量。重启只清基线，保留
同模型累计。缺少稳定电池身份时不能识别全部换电；用户应重新配置模型以建立新基线。
跨日/月的有效区间按接收时间归桶，明确是估算，不宣称精确分摊。

## 新增、隐私与验证定位

普通续航range_estimated、AI续航range_ai分别取estimate_mileage/ai_estimate_mileage，
单位km、MEASUREMENT，默认关闭。charging_power_raw默认关闭，无单位、无统计。
列表/profile数据、status、battery与travel分别归一化，不把整份raw response存入属性。

定位需要用户明确选项；参考坐标系未证实，不自动转换。diagnostics不输出电话、SN、
业务uid、VIN、MAC、蓝牙密钥、token、密码、坐标、argv或上游错误正文。公开fixtures
使用合成身份。表中各控制动作仅验证调用、互斥、错误与生命周期，未验证硬件效果。

## v2.x 补充

本表以上为2.0.0b0历史基线。2.0.0b1保留所有实体身份与观测含义，但收敛
控制权限：未知support/permission/semantics默认拒绝；旧Lock不执行engine
命令。详情见[v2.x实施记录](v2x-实施与验收记录.md)，不将旧mock验证视为
实车lock/unlock等价证据。

2.0.0b3新增last_ride_duration/start/end/max_speed/average_speed各自独立sensor
unique_id `{sn}_{key}`，默认禁用；不复用旧energy/lock/last_mileage身份。
旧last_mileage在有可靠时间的response上按时间排序选最近ride，无时间时保留
last returned兼容含义；新5个实体不会借未知行序创建已完成行程数据。
